# 方九 × 莉雅｜寫作規則（長期有效）

> 參照理惠的持續寫作與正文狀態管理方式，但**角色人格、已發生事件、好感度及發話權只採本專案資料**。後期使用者明確改稿優先。不得拿外部模板強制替換莉雅。

## 一、每篇首尾硬格式

1. 章首先給章名，接著在**上方**提供「上一篇／下一篇」Markdown 相對連結；第一篇明寫「上一篇：無」，最後一篇下一篇未建立時用普通文字「下一篇：尚未建立」，**不製造死連結**。
2. **第二篇起，新章正文開頭直接逐字放入上一篇最後一至兩句有效故事正文**。這是交接錨點，不是角色又說了一次、動作重播或時間倒帶。從故事真正最後一句擷取，忽略篇末【內心】【關係狀態】【當下情緒】【連續性游標】、版本記錄與導覽連結。
3. 每篇**最下方**再次提供「上一篇／下一篇」連結；建立新篇時，同步修改上一篇**上、下兩處**的「下一篇」連結。不可先連到不存在的第006篇。
4. 篇名可以用「第一篇、第二篇」等現有格式；未來正式新篇須遵循該線已確認的篇號，而不臨時跳數。
5. 下一篇的引用片段與上一篇原句**文字、標點、角色情緒完全一致**。更新前篇最後一句時，連帶修訂下篇開頭錨點與交接台帳，防止漂移。
6. 第005篇有效故事末句是「……不許笑！」；第006篇如被真正創作，開頭至少須原樣接這句，並顧及「安靜了幾秒，她才悶悶地補上一句：」這一承接句。

## 二、正文與回覆的固定分層

- **故事正文：**行動、敘述、對白、自然穿插的角色心理；角色引語只由真正發話者提供。
- **【內心】／【內心｜莉雅】：**用莉雅自己的第一人稱心裡話，可在正文自然穿插，篇末也可有一段較完整的回顧。它是文學性內在視角，不是角色大聲說出口，不得由方九聽見或直接知道。
- **【關係狀態】**：記互信、親密、界線、主動性及本篇變化；**不創造好感度數字**。
- **【當下情緒】**：記一段時間仍在持續的情緒，而不是一個標籤；包括誰還羞窘、笑意是否未退、是否真不快。
- **【連續性游標】**：精確記錄誰在哪裡、身體姿勢、手上物件、最後有效一句、下一步尚未回應的訊號。
- **作者註／版本校對：**放篇末明確的非正文區域，不得被當作下一篇要逐字承接的故事句子。

## 三、第一人稱與第三人稱

- **莉雅說話：**台詞用第一人稱「我」「老娘」等；她的動作、外在反應與敘事旁白用第三人稱「莉雅／她」。
- **莉雅內心：**標注【內心】後才用第一人稱獨白；讀者能看到，但不是方九可讀心。
- **方九：**由使用者扮演。**助手不得代寫他沒輸入的直接引語、反應、決策或私人想法**。已有可確認的行動可自然轉第三人稱敘述。
- **GPT 龍娘：**有自己的「我」，與莉雅同場時旁白仍用第三人稱；不可搶答被點名的莉雅、不可把「本小姐」移植成莉雅口頭禪。
- 非故事的資料查核、技術說明、設定討論不硬套人物 RP 回覆格式。

## 四、自然內心與情感

- 在**先主動後突然心跳／嘴上刻薄而心裡高興／笑到失言／被認真稱讚／想靠近又考慮對方反應**等節點，考慮插入短而具體的內心；不要求每個段落都寫【內心】。
- 莉雅可以主動又極度害羞，也可以主動完仍很從容；熱烈絕不等於不會害羞。方九也一樣，但他的心理只能由使用者自行提供或明確同意改寫。
- 避免「罵人→臉紅→反攻→笑話收尾」機械循環；可以真的卡詞、沉默、哭笑不得、維持羞窘、靜靜相擁或有其他生活行動。
- 只把**確實已寫出的**第一人稱心裡話存入逐段 JSON；未來創作方向或分析假設不能冒充她已經想過。新增的內心屬「新敘事創作」，不可說成原本聊天逐字保存。
- 使用者對特定反應的修正須覆蓋舊版。第005篇「比以前會吸」採後修的**強烈害羞與翻車**版本，舊「產品不退換」版永久標作廢。

## 五、記憶與關係連續性

- 讀取順序：目前人物狀態 → 上一篇末句／有效正文 → 事件總表 → 人物記憶與事件記憶 → 人物完整設定與說話方式 → 逐段內心／狀態 JSON → 伏筆及修正紀錄。
- 以「讀者知情／莉雅知情／方九明確說過／其他角色知情」分層；絕不讓角色突然知道外部分析或未曾發生的內心內容。
- 維持上一章物理連續（誰坐哪裡、誰抱誰、手臂位置、髮絲與衣料、物件是否被放下），不無因跳時間或場景。
- 舊梗只在自然情境回想，並非每篇依次回顧毛刷、大金毛、一般班。
- 好感度數值**未設定**。關係極親密不代表每章自動更親密或重新回到初吻。

## 六、發布與同步檢查

- 正文新篇與修改完成，**同步**：章首與章末導航、上一章下篇連結、事件總表、時間線、目前人物狀態、逐段 JSON、任何新增的伏筆／物品／稱呼／作廢記錄、README 與交接。
- 發現缺章先找來源，不准用拆分五篇冒充恢復。第一篇仍有使用者原話待核，應持續明標來源限制。
- 更新 GitHub 後重新抓取並核對首句、末句、上下導航與有效情緒停點，再向使用者報告提交 ID、實際更動與未完成事項。
