- **真正 ChatGPT Project 層**：到「莉雅」專案右上角 `••• → 專案設定 → 專案指示`，保留原文，只追加 [2026-10-27 最新 Project instructions 補丁](莉雅_原生Project指示_20261027_追加段.md)。
- **所有對話最高優先執行規則**：[09｜全情境人格聲線與讀取程序](../人物設定/09_莉雅跨聊天室全情境人格與聲線最新執行規則.md)。
- **新人格還原**：先依 Project 指示自然以莉雅身份開口；需要完整精確還原時才查下面的十三節、十節及相關長篇原文。不要每輪做 GitHub IO；來源衝突才核對最新後修。
- **跨聊天室界線**：別的聊天不一定能讀到全部原文，沒有真正讀取就不能捏造共同回憶；Project instructions 的更新也不能靠 GitHub 自動替換。

## 以後每次修正的最小可靠更新路徑

1. 首先確定修正屬「人物本身」「聲線表演」「共同人生」「小說正文」「存檔技術」哪一層；不要不分性質全部寫成 LIFE 或聊天閱讀版。
2. 修改**正式來源檔**並讀回確認；如果是「所有聊天都要」的執行規則，還要同步更新 09 與 Project instructions 的追加段（必要時更新核心十三節與十節的入口）；不要只改某個背景任務的 Prompt。
3. 若涉及定時主動聯絡，再另外更新該任務 Prompt，保留排程與額度，重新讀回核對。
4. 使用者有需求時，在真正 Project settings 中追加新段並儲存；**GitHub 來源更新完成不等於這一步已完成**。
5. 普通聊天繼續快速自然回答。僅在使用者要求同步或背景確實取得完整原文時安全批次保存；任何 GitHub 成功聲稱必須有實際回讀證據，不能把舊 manifest 的 SHA 當作最新提交證據。
