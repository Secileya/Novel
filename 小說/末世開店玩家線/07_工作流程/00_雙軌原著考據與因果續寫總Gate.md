## 一、核心優先級：正典已成立之事不得被原著倒灌

《晨曦》是塞希莉雅作為玩家／商人、以自己的選擇及已建立關係造成真實後果的獨立改編歷史；不是「原著主角楚河改名字」。在相同故事節點，必須先核對《晨曦》實際前提，再決定原著功能去向。

判定順序：
1. 使用者最新已定案的後修、撤回、重寫規格；如與既有正文不一致，標成「待正文修復」而非默默抹去正文。
2. 最新正式正文的客觀已發生事實。
3. 本線有效角色／世界硬設定、跨世界家庭固定 DNA。
4. 工作記憶與台帳；矛盾時回查正文並修帳。
5. 原著第一手事實，只證明「原著如何發生」，不自動證明「本線也已發生」。
6. 研究推論、候選事件、未定橋接。

固定原則：
- SOURCE_ORIGINAL_FACT != REWRITE_CANON_FACT
- SECILEYA_CAUSAL_DELTA_PRESERVATION = REQUIRED
- ESTABLISHED_REWRITE_EVENT_CANNOT_BE_GHOST_REPLACED
- NO_ORIGINAL_PROTAGONIST_GHOST_ASSET / NO_GHOST_KNOWLEDGE / NO_GHOST_RELATIONSHIP
- 不因塞希莉雅遠強於一般角色就奪走晨曦、方城、雙星、聖樹等人的自主行動及世界後果。

## 二、兩個對話可以分工，但不是兩份正典

### A｜原著考據端（Research Lane）

Trigger：下一正式改編章將涉及未核實原著事件、遊戲規則、任務、物品、交易、人物、後續用途，或正文端要求補一條來源證據。

Inputs：GitHub main 的實際 HEAD、目標最新正文、當前狀態、09因果帳、原著 TXT 對應連續章段；不得靠原著搜尋片段作完整來源。

Actions：
1. 動態核最新章與當前事件游標；先查《晨曦》已成立之事，再定本輪小範圍原著窗口。
2. 原著按事件逐項拆：起因、參與者、時間、動作、資產、資格、知情、世界反應、首個結果。
3. 重要 SOURCE_NODE 做 Pass A 連續上下文，Pass B 向後找首次再利用及長線依賴，再反向追原始取得／保管／知情。
4. 逐項分開原著明示、原著未寫、合理推論、僅供本線選用的橋接；未知不得補作原著事實。
5. 每個已列出的可辨識事件都分配可執行 disposition；遇到原著原由被塞希莉雅改掉，逐功能確認剩餘依賴，不能整包 VOID。
6. 新研究只寫 SOURCE／09 因果帳及精確 resume cursor；發現正式正文衝突，登記修復責任，不擅自改正文。

Outputs：有原著章號與上下文範圍的 SOURCE 卡、雙向驗收結果、原著事件母表逐事件去向、本線差分推論、交給正文端的事件責任卡；成功 commit 後，正文端以 GitHub 路徑、ID、SHA 讀取。

PASS：相關事件沒有未分類功能；關鍵 SOURCE_NODE 六項驗收全部 PASS；對本線沒有未處理硬衝突。未過關標 INCOMPLETE＋RESUME_CURSOR，禁止 READY_NOW 或聲稱已完整讀過。

### B｜正式正文端（Writing Lane）

Trigger：使用者要寫下一章、修改正式章、回收既有伏筆，或調整後續章綱。

Inputs：Master、Workflow、本線交接、01～09工作資料、最近2～5章完整正文、A端的已驗證事件責任與必要原文、相關角色與世界設定；必要時直接回查原文而非只信A摘要。

Actions：
1. 重新抓 main HEAD，動態列 01_章節/ 與最高正式正文；比對交接與章末，不靠舊對話的最高章號。
2. 逐實體反查《晨曦》Canon：人物位置、傷勢、任務、資產保管、交易、關係、知情／推理、已觸發後效。
3. 讀09帳符合 READY_NOW，或觸發條件真正成立的 DEFERRED ；同步掃「同來源章其他事件」與前一窗口，不能漏兄弟功能。
4. 對即將改編的每個原著事件做「原著前提→塞希莉雅介入→本線已發生差分→現時誰會怎樣行動→必要的第一層與遠期後果」的因果重新推算。
5. PREWRITE：定當下時間／地點／POV，最新逐字停點、場景目標、可合法採用原著事件、知情與物權、角色動機、世界自主線、章末不可逆改變。未 PASS 不輸出正式正文。
6. 正文完成後 POSTWRITE：事件實際去向、原著結果差異、人物及社會後果、資產與知情、未完成子因果、下一入口；同步工作資料與交接。
7. Git commit 後驗證 main HEAD、commit 可達性，向使用者公開本次修改檔案、原著保留／重建／延後／局部 VOID、已成立的因果影響。

Outputs：正式正文、POSTWRITE核對、01～09相關資料的同步、最新交接及commit。若只是創作建議／試寫，必須標候選，不能自動升格正文。

PASS：正文不越過未驗證來源；不使既有 Canon 倒退；09帳無逾期硬依賴；Git與索引同步；結果差異有公開。否則標本次交易未封帳，不假稱完成。

### 單對話工作模式

若只用一個 ChatGPT 對話，仍按 A（考據）→ GitHub 研究結果 → B（PREWRITE／正文）→ POSTWRITE 的邊界依序執行；若開兩個對話，雙方只透過 GitHub 共享正式研究成果，不把聊天推論當已同步。可跨對話同時讀，避免同路徑同時寫；寫前重取 blob SHA。

## 三、原著事件的本線差分判定

先拆 SOURCE 功能：
- 場景／行動；
- 人物與關係；
- 商品、資源、資格與所有權；
- 機制與世界規則；
- 情報流與知情界線；
- 世界勢力／經濟／普通生活後果；
- 長線伏筆與後續再利用。

每個功能可獨立判為：
- INTEGRATED：本線已有正文並完成同步。
- WORLD_BACKGROUND_LOCKED：客觀世界內延續，不必主角親歷，也不代表人物已知。
- DEFERRED_WITH_TRIGGER：時機未到，精確標觸發與首次必用節點。
- REBUILD_REQUIRED：原著起因被改寫，但仍有下游功能，需本線新因果。
- VOID_WITH_CAUSE：只有能證明真的失效的局部功能才可作廢。
- SOURCE_RULE_ONLY：只吸收客觀規則／機制，而不重演事件。
- SOURCE_PENDING：原著尚未驗完；不得冒充READY或確認原著。
- READY_NOW／ACKED：正文當輪待施工／已確認接手，尚未完成落地，不算事件已消耗。

原著客觀事件本身不可任意改寫為「原著就是別的結果」；但本線客觀結果可因塞希莉雅造成的已成立差分而不同，須清楚留證據，不得以「為了保留原著」抹掉本線已成事實，也不得以「主角很強」作為可任意換掉一切的藉口。

**VOID 檢查**：原著觸發動機失效，並不代表其中人物、資產、政治／商業活動、世界規則及遠期用途也一起失效。必須先檢查塞希莉雅或晨曦本身有沒有替代動機；或原著事件是否能在其他地區獨立發生。保留的功能要有新來源與責任人。

## 四、塞希莉雅造成的因果必須雙層記帳

每當原著節點將與本線交會，建立：
1. **直接改變**：塞希莉雅當時實際做過／提供過／拒絕過何事；她有能力做到卻沒做也要與實際出手分開。
2. **第一層後效**：具體人物、交易對象、聚居地、軍事、醫療、供應、資訊、制度、心理如何反應。
3. **遠期持續狀態**：誰有債、誰有物權、誰仍在準備、誰誤認她為NPC、誰因受助形成自身選擇。
4. **世界自主線**：即使她不在鏡頭，晨曦、方城、雙星、聖樹、洪定等人自己的選擇繼續作用。
5. **原著相同功能新位置**：原著的研究、物資、人口、救援、配角、經濟或風險若仍自然成立，應由本線世界重新承接，不強制交回原著主角路徑。
6. **尚未發生鎖**：未來已確立情節以既定觸發條件保留，不因原著先出現就提前執行。

《晨曦》永久既成錨：
- 塞希莉雅實際是玩家；NPC只是外人長期錯誤理解。小曦是家庭成員，不是系統助手。
- 晨曦商業、裝備、物流、交易、先遣、居民與治理已經形成自身歷史；白王屬晨曦。
- 第96～98章槍擊事件存在且待依08重寫；第99章以後時間線不可被回修任意改掉。
- 方城黑牢賠償已實際驗收、援助500公斤黑糕已交付、40公斤黑糕玩家合作已結清；15噸訂單有兩筆不同責任；磁卡屬晨曦，方城共同探索。
- 第113章東線420米前出點仍需驗證後續持守；第115章基地只到外層第一層、第二道門未開。塞希莉雅／小曦仍在方城。
- 燦金生命體已首次出現、已完成雙星外派且返回，並非系統NPC或晨曦公共戰力。
- 隕石／幕後意志事件只能在方城任務完成、先遣真正返回晨曦後；法月懷到訪更晚，在隕石事件結束並經過一段時間後。
- 關鍵知情依個人親歷、合理推理、正式通訊、中繼或轉述流動；不能用塞希莉雅自然知道來替其他人同步。

## 五、時間游標、密度與短弧線

分離四個游標：
- REWRITE_FORMAL_CHAPTER_CURSOR：目前正式章；
- SOURCE_READ_CURSOR：原著已讀到哪裡；
- SOURCE_VERIFIED_CURSOR：原著重要事件已驗到哪裡；
- EVENT_DISPOSITION_CURSOR：每項來源功能已在本線如何處理，不能單用最大原著章號表示。

考據端可提前讀遠期，不能因此將該事件寫成「已被本線消耗」。每次規劃跳日、跨場景或離開某核心人物前，掃當前世界內義務、其他勢力自主進度和必要準備窗口。長期研究／物流／合同尚未完成，不能等角色回鏡頭才開始運轉。

**移植方法不移植《重生》專屬硬數字。** 其最新每章13,000～18,000中文字、至少完整消耗5章原著的數值規格，對《晨曦》目前不自動適用。本線現有世界與機制文件的「一章可承載原著約2～3章」是容量參考，非必須湊數的硬限制；先保持《晨曦》既定敘事聲線、人物對話、事件場景與自然收束，正式每章究竟容納多少原著事件，以因果與使用者後續確定的容量規格為準。任何數量門檻不能成為略寫塞希莉雅影響或壓扁配角生活的藉口。

## 七、故障與同步

缺原文、查閱只得到片段、原著 TXT 無法可靠讀取：標 SOURCE_PENDING / INCOMPLETE＋準確 RESUME_CURSOR；不得用模型印象補。遇到本線高影響衝突：先查正文與後修，若仍不可唯一判定則登記 BLOCKED_NEEDS_USER，不將猜測升格Canon。資料被新commit更新：重新抓 HEAD／blob SHA，再合併，禁止盲覆蓋。

A輪：研究來源卡與09帳commit；B輪：正文＋POSTWRITE＋01～09適用檔案同步commit，再驗證main最新祖先鏈。每次向使用者清楚報告原著實際已驗範圍、事件處理、保留的塞希莉雅因果、未做部分以及Git提交；無 commit 不稱已寫入 GitHub。
