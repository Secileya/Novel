## 二、動態現行狀態的核心要求：必須回答「在哪條世界線、何時、證據到哪裡」
**現行不是固定人物卡**。查詢輸入至少：`CANON_STREAM`、`AS_OF`、`ENTITY`、`FIELD`，選擇性 `LOCATION/DOMAIN`。沒有 `AS_OF` 的「現在」不准預設成原著結尾、資料檔最後一行或寫作 C0。

- **故事／版本座標** `CANON_STREAM`：`PWCLU_NOVEL`、`SL_ANIME`、`SL_NOVEL`、`TLN_WEBTOON`、`ORV_NOVEL_TC`、`FUSION_AU` 等；正式小說、網漫、動畫、遊戲即使同名也是分開的平行記錄，彼此可參考但不自動覆寫。
- **原著發生座標** `SOURCE_TIME`：例如 `PWCLU_NOVEL_CH13_END`、`CH14_AUCTION_AFTER`、`CH16_CONTRACT_AFTER`、`CH19_GATE_CLEAR_AFTER`、`CH20_MEDICAL_VISIT`。一章內有先後須加節點 `#01/#02`；有「一個月、四天、兩週」必須保留真實相對時距，不把一章當一天。回歸／歷史重寫另設 `HISTORY_BRANCH`，不把失效歷史覆寫現行分支。
- **融合 AU 座標** `AU_TIME`：`C-DAY -14/C-1/C0/C+3...`、實際正式章和事件 ID。**不允許因研究到原著 ch20 而把它自動變成 AU C0 已發生**；只有主小說正式 `CANON_OCCURRED`／使用者明確裁決才能改 AU 歷史。
- **研究觀察座標** `RESEARCH_REVISION`：Git commit／查證日期、改正誰的舊主張。Git 最新不等於故事中最近，補讀舊章會改正過去快照而不表示人物在小說時間重新取得物品。

## 三、原著研究事件真源（EVENT_SOURCE）→ 狀態差分（DELTA）→ 指定時間快照（AS_OF_SNAPSHOT）
建議每個具有重要因果或會轉手的事件使用如下欄位，按需要精簡，不為所有飲食日用品建立百科：
```text
EVENT_ID / CLAIM_ID:
CANON_STREAM / MEDIA_VERSION:
SOURCE_URL / CHAPTER / EXACT_VISIBLE_RANGE / EVIDENCE=P0|P1|P2|P3|OPEN:
SOURCE_TIME / ORDER_IN_CHAPTER / ELAPSED_DURATION / HISTORY_BRANCH:
ACTOR / PRECONDITION / ACTION / FAILURE_OR_REFUSAL:
ENTITY_ID / FIELD:
BEFORE_VALUE / DELTA / AFTER_VALUE:
LEGAL_OWNER / PHYSICAL_HOLDER / WEARER / USER / USAGE_PERMISSION:
ACQUIRED / SYNC_RESULT / SOLD / GIFTED / LENT / RETURNED / LOST / CONSUMED / DESTROYED:
BALANCE_TYPE=RECEIPT|QUOTE|PAID|CASH|BANK|DEBT|PROMISE / AMOUNT / UNIT:
KNOWS_BEFORE / WITNESSES / WHO_KNOWS_AFTER / PRIVATE_INFO:
IMMEDIATE_CONSEQUENCE / CONTINUING_OBLIGATION / DOWNSTREAM_SOURCE_DEPENDENCIES:
VALID_FROM / VALID_TO_WHEN_PROVEN / LAST_CONFIRMED_AT / UNCERTAINTY_AFTER:
COUNTEREXAMPLE_CHECK / CONFLICT_QUARANTINE / SUPERSEDES:
AU_MAPPING=NONE|PROPOSAL|APPROVED|CANON_OCCURRED / AU_EVENT_ID:
```
每條來源事件**不可直接改掉歷史**；後面新增同物／同人的事件按來源時序寫入，指定 `AS_OF` 由合法先前事件回放，差分後生成。在來源缺章、身分可能已轉移、數量可能已消耗或時間期限已過時，當下顯示 **`LAST_CONFIRMED`＋`CURRENT_AS_OF_OPEN`**，不能自動延長未被證實的物件持有。「無證據顯示離手」不是「證明從未離手」。

### 狀態判準
- `PROVEN_AT_TIME`：在來源可見的該時點直接確定（如 ch14 匕首拍賣成交）；只承擔該事件和確定後果。
- `INHERITED_WITH_COVERAGE`：有完整或足以排除相關轉手的後續證據，可有界延續。若中間尚未讀的章可能發生交易，不能強行說完全確定。
- `LAST_CONFIRMED_THEN_OPEN`：如 ch13 母親親自戴護身符；ch19 佩戴是否仍在無直接核證。
- `NOT_ACQUIRED`／`SYNC_FAILED`／`OFFER_NOT_PAID`／`SOLD_CONFIRMED`／`CONSUMED_CONFIRMED`：負面和離手事件同等重要。
- `CONFLICT_QUARANTINE`：證據矛盾、媒介衝突或快照漏前史；禁止偽裝成 `VERIFIED_CURRENT`。
- `PROPOSED_AU`：作者可提出的未來分歧，**不表示故事已發生**。

### 時間自然推進的特殊情況
- **失效日／截止時間**：若來源明示某權利有效五日，需記期限，逾期依原著條款或 AU 已成立事件判定，不因未出現新章就永久續期；具體開始／結束時間未知時不偽造日期。
- **有條件變動**：受傷恢復、按期付款、租約與組織政策、外界救援、塔內離鏡生活可能隨時間改變；**時間流逝本身不證明結果已發生**。只有來源／已承認 AU 事件／可證的有效期規則才能轉移；其他列 `TIME_ELAPSED_REVIEW_REQUIRED`，並開跟查。
- **人物離鏡仍生活**：不凍結其活動，但沒有原著或正式 AU 事件時也不代替人物編造收入、練級、還款、交友、取得道具。

## 五、每次查詢／研究如何真正驗收
1. 先選原著／改編／AU 的**獨立版本及時間點**，找 `ENTITY`，列最後確認的每個欄位及足以推翻它的離手／拒絕／失效事件。
2. 往前找完整取得過程，往後追使用／轉手／損耗／交易；必要的中間章未核時，僅顯示 `LAST_CONFIRMED`，**不可產出無條件「當前持有」**。
3. 查看 `KNOWS_BY_PERSON_AT_TIME`；讀者或作者知道的原著未來，不等於角色當時知道。
4. 用反例庫至少一項 F-01～F-14 對抗核查。`VERIFIED` 是結論不是來源，回查 `CLAIM_ID` 支持範圍。
5. 若主小說真正寫成一章，先以主對話 `POSTWRITE` 的 `CANON_OCCURRED` 差分更新 AU；研究庫只提交有來源的原著層或提交衝突單，不自行動 AU、家庭與寫作游標。
6. 修改來源後追依賴 `12_→03_→05_→02_→10_→00_/CHANGELOG`，按實際受影響範圍修；GitHub 讀回驗證變更。**本版僅建立研究端可實作框架及示範；五作全部具體事件的台帳尚未完成填入。**
