# 後續卷動態規劃協議

> 目的：讓沒有舊對話上下文的普通對話，也能像第一卷一樣完整規劃第二卷、第三卷及更後面的卷；每次只規劃「目前下一個未完成卷」，完成後留下可再次接續的動態游標。

## 1. 核心原則

1. **一卷一交易。** 每次完成一卷的入口、主題、階段、事件依賴、六線演化、社會後果、高潮、收束與證據債；不可只給幾個靈感便把狀態標成完成。
2. **規劃不是已發生。** `PROPOSED`、`AU_LOCKED_FOR_OUTLINE` 與 `CANON_OCCURRED` 必須分開。
3. **動態找下一卷。** 不把提示詞永遠寫死為第二卷；先讀卷級索引，若已有未完成卷便從其中斷點繼續。
4. **前卷實際終態優先。** 有正文便用章後 ACK；沒有正文只能用預計終態，並標 `PROJECTED_ENTRY_STATE`。
5. **五線繼續生活。** 沒有幕前出場的原著線仍需 `OFFSCREEN_ACTIVE + NEXT_CAUSAL_ACTION`，不能因 Franiya 或另一作搶走鏡頭而停止。
6. **Franiya 是系列主角。** 不要求每章出場，但整卷必須改變她的生活、選擇、關係或她所處世界；不能把她降成跨作嘉賓。
7. **原作事實與 AU 分開。** 未核部分標 `SOURCE_UNSTATED`；可使用最小、可撤回的 AU 過橋，但不得冒充原作。
8. **不預設全書卷數。** `SERIES_TOTAL_VOLUME_COUNT` 在真正建立全系列終局前保持 `UNDECIDED`。

## 2. 普通對話的必讀順序

規劃下一卷前，普通對話至少依序讀取：

1. `../00_專案交接與最新進度.md`
2. `../13_版本紀錄與原對話交接/12_專案交接_v0.6.0_普通對話與後續卷規劃.md`
3. `00_卷級索引與續接游標.md`
4. 上一卷完整規劃檔；若已有正文，再讀該卷最後一章及章後 ACK
5. `../14_寫作流程與劇情引擎/02_原著事件適應器與五線同步.md`
6. `../09_事件台帳與未完成因果/` 中仍開放的因果
7. `../03_原著人物與關係聲線/`、`../05_力量系統與交互規則/`、`../06_時間回歸與世界線/`
8. `../07_Franiya角色適用規則.md`，並讀取 `../../家庭總檔/01_家庭完整角色設定總檔.md` 的「十五、芙蘭妮雅完整人物資料」與「16.1.9 芙蘭妮雅」
9. `../12_原作證據與譯名/00_來源與譯名索引.md` 及本卷會實際使用的 `SOURCE_NODE`

若任何必讀檔無法開啟，列出未讀檔。可以處理不依賴缺檔的部分，但不得宣稱完成整卷規劃。

## 3. 下一卷規劃交易

### Pass A｜入口狀態凍結

先列出：

- 前一卷是 `CANON_OCCURRED_END_STATE` 還是 `PROJECTED_END_STATE`。
- 六線與 Franiya 的位置、時間、知識、關係、資產、義務及下一個被迫行動。
- 社會制度、難民、交通、醫療、經濟、犯罪與輿論的累積狀態。
- 尚未償還的 `INTERIOR_DEBT`、`RETURN_CAUSE`、物件持有鏈與來源 Gate。

缺少任何一項時，先記為本卷的入口債，不得默認恢復原作狀態。

### Pass B｜本卷存在理由

必須回答：

1. 若刪掉這一卷，全系列會失去哪個不可替代的變化？
2. Franiya 的長期角色弧在本卷改變什麼？
3. 哪兩至三條原著線在幕前，其他線如何在幕後推進？
4. 本卷保留哪些原著核心壓力，又因共同世界改變哪些前提？
5. 本卷高潮解決的是選擇與責任，還是只有戰力大小？

回答若只能寫成「大家再遇到一個更強敵人」，本卷不通過。

### Pass C｜階段與事件依賴

- 建立五至九個推進階段；章數只能作節奏預算，不得為湊章數拆碎。
- 建立有順序、有前件的事件佇列；每個事件標 `原作事實／融合AU改編／待原作查證`。
- 階段可有多種驅動器，如共同事件、原著人物壓力、普通生活、社會後果、Franiya 的選擇；**不要求每階段機械湊到至少兩類**。只要人物及事件有真實延續和合理因果，單一生活線也可承擔有重量的篇章。
- 原著事件使用八種適應狀態：`PRESERVED`、`PRESERVED_WITH_CONTEXT`、`ADVANCED`、`DELAYED`、`REROUTED`、`SUBSTITUTED`、`CANCELLED`、`BRANCH_ONLY`。

### Pass D｜人物、視角與關係

- 每個主要場景預先分開 `POV_OWNER / ACTION_OWNER / ARC_OWNER`。
- 安排本卷的信任、衝突、義務、誤判與界線里程碑；不能只寫「關係加深」。
- 新增主視角前檢查三個連續原文聲線窗口；不足時改採受限視角或標來源 Gate。
- 旁觀視角無權讀取當事人內心；欠下的動機以 `INTERIOR_DEBT` 記錄償還方式。

### Pass E｜系統、資產與社會

- 對本卷**真正將登場／轉手／跨系統使用的重要**物品、技能、Ego、獎勵與契約按需核取得、持有、啟用、人格／權限及時序；普通日常物件不強制填完整物件台帳，沒用到的後期神器不阻塞規劃。
- 跨作取得仍經 `DISPLAY → REGISTRATION → REWARD → PERSISTENCE`。
- 每個大型事件至少結算交通、通訊、醫療、政府、公會、物價、黑市、犯罪、媒體與普通人中的相關項目。
- 跨線影響必須有物理、報告、傳聞、資源、系統、人／物轉手或時間接觸邊；無接觸邊不得共享作者知識。

### Pass F｜高潮與收束

卷末必須固定：

- 地點、時間、直接參與線、間接受影響線。
- 誰作不可替代的決定，誰承擔代價。
- Franiya 的介入模式及她選擇不做的事。
- 系統／制度／人物衝突如何被部分解決，哪些債進入下一卷。
- 不可逆終態，以及為何不會自動形成全員固定隊或全知共享。

### Pass G｜一致性測試與鎖定

至少執行：

1. 時間與地理可達性。
2. 人物知識邊界。
3. 原作事件前件與下游依賴。
4. 物品／能力持有鏈。
5. Franiya 本體與主觀時間連續性。
6. SSS 高塔不可自由進出。
7. 五系統後台不自動合併。
8. 社會與普通人後果不消失。
9. 無 Franiya 場景的主線回接功能。
10. 移除 Franiya 後世界仍能活動，但加入她後本卷又確實不同。
11. 卷末是否產生可驗證的狀態差，而非回到原點。
12. 未核原作內容是否全部標為來源債。

全數通過後，才可把該卷從 `PROPOSED` 升為 `AU_LOCKED_FOR_OUTLINE`。

## 4. 一份「完整卷規劃」的最低交付物

普通對話不得只交摘要。至少需要：

1. 卷名或工作名、規劃狀態及入口狀態類型。
2. 故事內時間窗、建議章數與節奏理由。
3. 本卷命題、Franiya 主線變化及不處理事項。
4. 六線入口狀態與卷末預計狀態。
5. 五至九個推進階段。
6. 有依賴順序的主要事件佇列。
7. 幕前／幕後線配置與跨線接觸邊。
8. 主要人物的視角、行動與角色弧所有權。
9. 關係里程碑與知識差。
10. 技能、物品、召喚物、介面及契約持有鏈。
11. 制度、普通人、經濟、文化、犯罪與媒體後果。
12. 原著事件的保留／改道／取消台帳。
13. 卷末高潮硬規格。
14. 卷末不可逆差分與下一卷強制前件。
15. 來源 Gate、`SOURCE_UNSTATED` 與尚待使用者決定的真正創作分岔。
16. 一致性測試結果、版本變更與下一個 `VOLUME_PLAN_RESUME_CURSOR`。

## 5. 提案、鎖定與正文的狀態詞

```text
NOT_PLANNED                尚未規劃
IN_PROGRESS                規劃中，必須有精確中斷游標
PROPOSED_PARTIAL           已有部分方案，但尚未達到完整卷規劃最低交付
PROPOSED                   完整方案已出，但尚未成為唯一現行卷綱
AU_LOCKED_FOR_OUTLINE      已成為現行可執行卷綱，但尚未發生
PREWRITE_ACTIVE            已進入逐章章前施工
PARTIALLY_CANON_OCCURRED   本卷已有正式章，後段規劃仍可回基線
CANON_OCCURRED_COMPLETE    全卷正文與章後 ACK 完成
DOWNSTREAM_REBASE_REQUIRED 前卷實際差分使本卷部分前提失效
```

普通對話可在證據足夠時提出完整 `PROPOSED` 方案；除非使用者已授權「直接推演解決／採用」，不得自行把重大創作分岔標為使用者確認。已被明確確認的 Franiya、世界線、高塔與敘事規則不可重新投票。

## 6. GitHub 寫入與無寫入能力時的交付

- 有寫入能力：建立新卷檔、更新索引、總入口、交接與變更紀錄，驗證連結後再回報。
- 無寫入能力：輸出完整可保存的 Markdown 卷規劃，以及逐檔更新清單；明確標示 `NOT_SAVED_TO_GITHUB`，不得說已保存。
- 不論能否寫入，都必須留下下一個精確規劃游標，不得只說「之後繼續補」。
