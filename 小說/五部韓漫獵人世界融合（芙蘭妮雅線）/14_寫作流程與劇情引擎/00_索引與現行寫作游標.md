## 3. 動態續寫規則

每次新對話或中斷接回時，按以下順序找游標：

1. 掃描 `../11_正式章節/`，找最後一個明確標為正式採納的完整章。
2. 讀該章末尾的 `POSTWRITE`／交接；若缺失，從正文反推並先補狀態差分，不直接續寫。
3. 讀本檔的 `RESUME_CURSOR`、事件台帳中對應事件卡，以及該事件所需的 `SOURCE_NODE`。
4. 若仍無正式章，讀本檔現行 `RESUME_CURSOR`；v0.4.1 應回到 `DRAFT_FULL_CHAPTER_001_FROM_EVT-ENTRY-FRANIYA-001`，不得退回已完成的聲線 Gate。
5. 不以聊天中曾出現的示範片段、舊提案或負例充當最新正式章。

## 4. 狀態詞只有下列意義

| 狀態 | 意義 |
|---|---|
| `PROPOSED` | 尚可自由更換的助手／作者提案。 |
| `AU_LOCKED_FOR_OUTLINE` | 已納入卷級因果，可排章，但細節仍可在不破壞依賴時調整。 |
| `AU_LOCKED_FOR_DRAFT` | 章前條件已足，完成列明來源／聲線 Gate 後可寫正文。 |
| `PREWRITE_READY` | 本章視角、目標、阻礙、選擇、結算與來源邊界都已填完。 |
| `CANON_OCCURRED` | 事件已進正式章，章後狀態也已同步；只有這一狀態代表「故事中已發生」。 |
| `SUPERSEDED` | 被後期明確修正取代，保留追溯但不再供續寫。 |
