# 長篇章節交易流程

> **[專案規則]** 一章不是單純產生文字，而是一筆「讀取既有狀態 → 角色作出選擇 → 世界狀態改變 → 所有受影響線完成結算」的交易。正文漂亮但沒有狀態變化，或事件刺激很大卻沒有後續帳，皆視為未完成。

## 1. 最小有效讀取包

每次寫新章前，至少讀取：

1. `../00_專案交接與最新進度.md` 與本資料夾 `00_索引與現行寫作游標.md`。
2. `../02_五部原著事件時間線/01_v0.3起始游標與演化台帳.md`。
3. 本章視角人物與在場人物的狀態／聲線檔。
4. 本章涉及的力量、時間、地理與進出域規則；沒涉及的不全量重讀。
5. `../08_正文文風與對話表演.md`、事件台帳與對應事件卡。
6. 本章會消耗的所有 `SOURCE_NODE`；遇到 `SOURCE_UNSTATED` 必須停在邊界內。
7. `../../家庭總檔/01_家庭完整角色設定總檔.md` 中 Franiya 章；若本章涉及專題能力，再追加相應補充檔。
8. 最後一章正式正文及其章後差分。若目前無正文，讀第一章章前包。

優先順序固定為：**明確作廢／撤回 ＞ 後期明確修正 ＞ 後期較完整補充 ＞ 早期仍相容設定 ＞ 尚未採納提案**。

## 2. 章前六道來源閉環

只要本章直接重演、改寫或取消原著事件，以下六項全部通過才可標 `PREWRITE_READY`：

```text
LOCAL_SEQUENCE_PASS       # 原著事件前後順序與必要前提已核對
CUSTODY_CHAIN_PASS        # 關鍵物件、能力、身分與人員在誰手上已核對
KNOWLEDGE_BOUNDARY_PASS   # 每人此刻實際知道什麼已核對
DOWNSTREAM_REUSE_PASS     # 原著後續還會依賴哪些結果已列出
UNSTATED_EDGE_MARKED      # 原作沒說的過橋明標 SOURCE_UNSTATED
FORMAL_CONFLICT_CHECK_PASS# 與本 AU 現行真源沒有互斥
```

任一失敗時：可以整理資料、排事件或寫純 AU 過橋，但不得把該原著節點寫成正式正文。

## 3. 章前規格

每章先回答十二題：

1. 這章開始時的精確日期、時段、位置與作用域是什麼？
2. 誰是主要感知者？為何他比其他人更應擁有這個視角？
3. 他在本章開始前已知、誤信與不知道什麼？
4. 他現在要完成的具體事情是什麼？
5. 哪個阻礙迫使他不能照原計畫完成？
6. 他必須作出哪個會暴露人格的選擇？
7. 選擇造成哪個立即結果與哪個代價？
8. 本章結束時，哪項狀態不可能回到章首？
9. 五條原作線與 Franiya 線各自是 `ON_SCREEN`、`OFFSCREEN_ACTIVE` 或 `NOT_YET_TRIGGERED`？
10. 原著事件狀態是保留、帶背景保留、提前、延後、改道、替代或取消？
11. 本章接觸他線的物理／制度／情報邊是什麼？沒有邊時，為何會知道？
12. 下一章不是「作者想切誰」，而是哪個未完成因果最先要求行動？

## 4. 場景推進核心

每個正式場景都走完這條鏈：

```text
GOAL 眼前目標
→ OBSTACLE 具體阻礙
→ CHOICE 角色可拒絕、會付代價的選擇
→ RESULT 可觀測的結果
→ COST 資源／關係／情報／時間／名聲／傷害之一
→ NEXT CAUSAL ACTION 因結果而不得不做的下一步
```

若只有刺激與反應、沒有選擇；或只有戰鬥勝負、沒有代價與下一步，該場景不能承擔長篇推進。

每章至少改變下列一項，最好兩項，但不為湊數全改：

- 外部局勢或角色目標；
- 知識、誤判或可安全說出的情報；
- 關係、信任、義務或敵意；
- 物件／能力／情報的持有鏈；
- 位置、進出權、身份或制度分類；
- 公共秩序、價格、交通、犯罪或組織資源；
- 原著來源游標或 AU 游標。

## 5. 視角與同時線數

- 一個場景只設一名主要感知者；換視角需換節並有因果理由。
- 視角優先給「要作選擇、最會承擔代價、或其知識缺口最能產生有效誤判」的人，不固定給 Franiya，也不固定輪流發便當。
- 一章幕前主動線以二至三條為上限；其餘線放入章末結算的 `OFFSCREEN_ACTIVE`，避免五作同章輪流報到。
- `OFFSCREEN_ACTIVE` 必須填下一個因果行動，不得寫「照原作發展」四字了事。
- 不在同一場的人，必須經由正式報告、影像、傳聞、物流、價格、失聯、系統通知或實體碰面取得他線影響。

## 6. Franiya 的五種介入模式

| 模式 | 可做的事 | 使用邊界 |
|---|---|---|
| `OBSERVER` | 自限觀察、保持生活、選擇不介入。 | 不把她寫成能力不足，也不要求她為旁觀自我辯護。 |
| `WITNESS` | 在場、記住、提供有限見證或拒答。 | 她的記憶與自我連續不能被回歸覆寫。 |
| `NEGOTIATOR` | 交換條件、設定界線、協助建立可行程序。 | 不自動受協會、公會、星流或高塔支配。 |
| `LIMITED_INTERVENTION` | 只處理她選定的人、物或局部危險。 | 必須寫清楚為何停在此處，以及未處理部分如何繼續。 |
| `DECISIVE_INTERVENTION` | 直接終止足以承擔的威脅或改寫局勢。 | 罕用；不能順手代替他人完成關係、罪責、選擇與成長，且必須留下制度與世界級後果。 |

她是否出手由關係、是否已被捲入、興趣／厭惡、成本、後果與當下意願共同決定；「有人受害」或「對方是惡人」本身不是強制按鈕。

## 7. 章後差分

完稿後先做差分，再宣布完成：

```text
CHAPTER_ID:
FORMAL_STATUS:
SOURCE_EVENTS_CONSUMED:
AU_EVENTS_OCCURRED:
TIME_AND_LOCATION_END:
KNOWLEDGE_DIFF:
RELATIONSHIP_DIFF:
ASSET_CUSTODY_DIFF:
ACCESS_AND_IDENTITY_DIFF:
SOCIAL_ECONOMIC_DIFF:
SYSTEM_OR_TIME_CLAIMS_CREATED:
FIVE_LINE_CURSOR_DIFF:
OPEN_CAUSES:
NEXT_FORCED_ACTION:
NEW_SOURCE_GATES:
```

接著同步：

1. 事件卡由 `PREWRITE_READY` 更新為 `CANON_OCCURRED`，或記錄只完成其中哪一段。
2. 更新五線與 Franiya 的來源／AU 雙游標。
3. 更新人物知識、關係、位置、資產與稱呼。
4. 更新普通人、制度、犯罪、文化與經濟後果。
5. 更新本資料夾 `RESUME_CURSOR` 與 `11_正式章節/README.md`。
6. 執行矛盾檢查後才建立 Git checkpoint；未推送成功不得稱遠端已保存。

## 8. 正文完成標準

- 使用者要求「開始寫／繼續」時，交付完整章，不交片段、提綱、`待續` 或「下一次再補」。
- 設定資訊必須經事件、誤判、選擇與代價顯露，不讓人物輪流作世界觀問答。
- 角色說出口的資訊不得超過其知識、信任、風險承受與當下時間。
- 反應之後至少改變站位、說法、信任、資訊、決策或下一步之一。
- 原著沒有寫明的過橋不得偽裝成原作事實；可用最小 AU 補橋，但要標記並接受後續修正。
