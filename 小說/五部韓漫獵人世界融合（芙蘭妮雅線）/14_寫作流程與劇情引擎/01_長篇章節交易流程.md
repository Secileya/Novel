# 長篇章節交易流程

> **[專案規則]** 一章不是單純產生文字，而是一筆「讀取既有狀態 → 角色作出選擇 → 世界狀態改變 → 所有受影響線完成結算」的交易。正文漂亮但沒有狀態變化，或事件刺激很大卻沒有後續帳，皆視為未完成。

## 1. 最小有效讀取包

每次寫新章前，至少讀取：

1. `../00_專案交接與最新進度.md` 與本資料夾 `00_索引與現行寫作游標.md`。
2. `../02_五部原著事件時間線/01_v0.3起始游標與演化台帳.md`。
3. 本章視角人物與在場人物的狀態／聲線檔。
4. 本章涉及的力量、時間、地理與進出域規則；沒涉及的不全量重讀。
5. `../08_正文文風與對話表演.md`、事件台帳與對應事件卡。
6. 本章會消耗的所有 `SOURCE_NODE`；遇到 `SOURCE_UNSTATED` 必須停在邊界內。
7. `../../家庭總檔/01_家庭完整角色設定總檔.md` 中 Franiya 章；若本章涉及專題能力，再追加相應補充檔。
8. 最後一章正式正文及其章後差分。若目前無正文，讀第一章章前包。

優先順序固定為：**明確作廢／撤回 ＞ 後期明確修正 ＞ 後期較完整補充 ＞ 早期仍相容設定 ＞ 尚未採納提案**。

## 2. 章前六道來源閉環

只要本章直接重演、改寫或取消原著事件，以下六項全部通過才可標 `PREWRITE_READY`：

```text
LOCAL_SEQUENCE_PASS       # 原著事件前後順序與必要前提已核對
CUSTODY_CHAIN_PASS        # 關鍵物件、能力、身分與人員在誰手上已核對
KNOWLEDGE_BOUNDARY_PASS   # 每人此刻實際知道什麼已核對
DOWNSTREAM_REUSE_PASS     # 原著後續還會依賴哪些結果已列出
UNSTATED_EDGE_MARKED      # 原作沒說的過橋明標 SOURCE_UNSTATED
FORMAL_CONFLICT_CHECK_PASS # 與本 AU 現行真源沒有互斥
```

任一失敗時：可以整理資料、排事件或寫純 AU 過橋，但不得把該原著節點寫成正式正文。

## 3. 章前規格

每章先回答十五題：

1. 這章開始時的精確日期、時段、位置與作用域是什麼？
2. 誰是主要感知者？為何他比其他人更應擁有這個視角？
3. 誰作出不可替代的決定？誰的長期角色弧被推進？是否與視角人物不同？
4. 本章承載哪個人物或生活事件？若與 Franiya 主軸自然相關則記錄；若獨立成立，記錄該線自己的延續價值。
5. 視角人物在本章開始前已知、誤信與不知道什麼？
6. 他現在要完成的具體事情是什麼？
7. 哪個阻礙迫使他不能照原計畫完成？
8. 行動所有者必須作出哪個會暴露人格的選擇？
9. 選擇造成哪個立即結果與哪個代價？
10. 本章結束時，哪項狀態不可能回到章首？
11. 五條原作線與 Franiya 線各自是 `ON_SCREEN`、`OFFSCREEN_ACTIVE` 或 `NOT_YET_TRIGGERED`？
12. 原著事件狀態是保留、帶背景保留、提前、延後、改道、替代或取消？
13. 本章接觸他線的物理／制度／情報邊是什麼？沒有邊時，為何會知道？
14. 是否留下當事人內心尚未揭露的 `INTERIOR_DEBT`？何種因果會要求回返？
15. 下一章不是「作者想切誰」，而是哪個未完成因果最先要求行動？

## 4. 場景推進核心

每個承擔**事件推進**的正式場景，原則上能追蹤以下因果鏈：

```text
GOAL 眼前目標
→ OBSTACLE 具體阻礙
→ CHOICE 角色可拒絕、會付代價的選擇
→ RESULT 可觀測的結果
→ COST 資源／關係／情報／時間／名聲／傷害之一
→ NEXT CAUSAL ACTION 因結果而不得不做的下一步
```

若只有刺激與反應、沒有選擇；或只有戰鬥勝負、沒有代價與下一步，通常不足以獨自承擔事件推進。但日常、旅途、閒聊、生活、關係、環境與獨立小事可有自身敘事功能，不必刻意加入危機或即時代價；驗收其人物、社會與情感的實際呈現，而非逐場硬套戰鬥式模板。

每章至少改變下列一項，最好兩項，但不為湊數全改：

- 外部局勢或角色目標；
- 知識、誤判或可安全說出的情報；
- 關係、信任、義務或敵意；
- 物件／能力／情報的持有鏈；
- 位置、進出權、身份或制度分類；
- 公共秩序、價格、交通、犯罪或組織資源；
- 原著來源游標或 AU 游標。

## 4A. 章節容量與零原作知識讀者 Gate（v0.6.1）

- **[使用者已確認]** 章節採高容量長章，一章可容納多個相連事件、豐富人物生活、社會反應與因果進展；不可把單一小事件重複描述到指定字數。事件卡可跨章，章內也可推進數個事件卡的階段。
- 常規長章約 8,000～12,000 中文字僅作容量參考，重要章可更長；切章依故事節點，不以固定場景數或事件數、字數最低值或兩章合併公式決定。
- 「第一章三場」及其他場次清單只是核心戲劇**功能**，不是限制全章只有三個場景。可以自然增加完整工作、社會、生活與次級事件；不得改寫既定時間線、前件或人物知情權。
- **[使用者已確認]** 以完全沒讀過五部原作的讀者為基準。系統和名詞初次參與情節時，要以角色的職務、行動、合理對話、可見後果或少量自然旁白交代最低必要背景；後續再分層深化。不能靠不解釋的術語堆砌，也不能在角色不知情時替其說破五作機密。
- 章前增列 `READER_BASELINE`、`NEW_TERMS_THIS_CHAPTER`、`MINIMUM_CONTEXT_DELIVERY`、`CHAPTER_SUBSTANTIVE_BEATS`；章後增列 `READER_CLARITY_PASS`、`CAPACITY_NOT_PADDING_PASS`。
- 零背景讀者測試：不查維基和設定檔，是否知道這一章人物為何如此選擇、關鍵規則大致是什麼、目前風險與結果？若否，應補足自然脈絡而非一次丟完整百科。

## 5. 視角與同時線數

- 全書採 `FRANIYA_CENTRIC_ENSEMBLE_MULTI_POV`：Franiya 是系列主角，群像是讓共同世界和他人主體性成立的敘事結構，不是平均分配戲份。
- 一個場景只設一名主要感知者；換視角需換節並有因果理由。
- 視角優先給「要作選擇、最會承擔代價、或其知識缺口最能產生有效誤判」的人，不固定給 Franiya，也不固定輪流發便當。
- 每場另標 `ACTION_OWNER` 與 `ARC_OWNER`。旁觀者可承載視角，卻不能替行動者決定，也不能把自己的推測冒充對方真實內心。
- **[v0.6.5 最新修訂]** Franiya 可以整章不出場；其他五作人物、中堅、基層或普通人亦可持有無需強制回接 Franiya 的完整故事。`MAINLINE_RELEVANCE / RETURN_CAUSE` 無自然因果可填 `NONE`，另追蹤本線自身的生活與人物弧。
- 非 Franiya 視角若推進她的角色弧，必須給她可見且可拒絕的實際選擇；不能只讓旁人替她定義性格、立場或需要。
- 一章幕前通常以二至三條主要線為合宜參考，但不設機械上限或數量下限；未出場線保留章後 `OFFSCREEN_ACTIVE` 的獨立因果。
- `OFFSCREEN_ACTIVE` 必須填下一個因果行動，不得寫「照原作發展」四字了事。
- 不在同一場的人，必須經由正式報告、影像、傳聞、物流、價格、失聯、系統通知或實體碰面取得他線影響。

## 6. Franiya 的五種介入模式

| 模式 | 可做的事 | 使用邊界 |
|---|---|---|
| `OBSERVER` | 自限觀察、保持生活、選擇不介入。 | 不把她寫成能力不足，也不要求她為旁觀自我辯護。 |
| `WITNESS` | 在場、記住、提供有限見證或拒答。 | 她的記憶與自我連續不能被回歸覆寫。 |
| `NEGOTIATOR` | 交換條件、設定界線、協助建立可行程序。 | 不自動受協會、公會、星流或高塔支配。 |
| `LIMITED_INTERVENTION` | 只處理她選定的人、物或局部危險。 | 必須寫清楚為何停在此處，以及未處理部分如何繼續。 |
| `DECISIVE_INTERVENTION` | 直接終止足以承擔的威脅或改寫局勢。 | 罕用；不能順手代替他人完成關係、罪責、選擇與成長，且必須留下制度與世界級後果。 |

她是否出手由關係、是否已被捲入、興趣／厭惡、成本、後果與當下意願共同決定；「有人受害」或「對方是惡人」本身不是強制按鈕。

## 6A. v0.6.5 獨立人物與生活場景修正

- 本作以 Franiya 為系列主角，但不要求每個獨立篇章、旁線、日常活動有刻意回接她本人的義務。其他五作角色、A/B/C 級獵人、學生、塔民、後勤、店家與普通人的生活可以完整成立。
- `MAINLINE_RELEVANCE / RETURN_CAUSE` 若自然存在則記錄，否則可 `NONE`；改以該線自身的 `INDEPENDENT_ARC_VALUE / CHARACTER_CONTINUITY / REAL_WORLD_STATE` 追蹤人物、工作與後果。『沒有永久代價的愉快日常』同樣可以是合格場景。
- 場景卡的『目標→阻礙→選擇→結果→代價』用於有明確事件的行動段，不把每次吃飯、交談、搭車、休息變成五欄 RPG 任務；日常有生活狀態與人物變化即可。
- 本卷 `C-14` 擴充只能加入當日已存在的生活、專業與合理小事件；`C0／C+3／C+7／C+11` 各大錨點必須維持時間，不可為充實第一章提前。
- 第一次跨作品物品／能力互用，新增 `ITEM_CUSTODY / ACQUISITION_TIME / DOMAIN_PERMISSION / ENERGY_OR_ACTIVATION / PERSONALITY_CONSENT / REMAINS_AFTER_EXIT` 審查，詳本專案 `05_力量系統與交互規則/03_五作重要裝備道具與跨域持有鏈_v0.6.5.md`。

## 7. 章後差分

完稿後先做差分，再宣布完成：

```text
CHAPTER_ID:
FORMAL_STATUS:
SOURCE_EVENTS_CONSUMED:
AU_EVENTS_OCCURRED:
TIME_AND_LOCATION_END:
KNOWLEDGE_DIFF:
RELATIONSHIP_DIFF:
ASSET_CUSTODY_DIFF:
ACCESS_AND_IDENTITY_DIFF:
SOCIAL_ECONOMIC_DIFF:
SYSTEM_OR_TIME_CLAIMS_CREATED:
FIVE_LINE_CURSOR_DIFF:
OPEN_CAUSES:
NEXT_FORCED_ACTION:
NEW_SOURCE_GATES:
```

接著同步：

1. 事件卡由 `PREWRITE_READY` 更新為 `CANON_OCCURRED`，或記錄只完成其中哪一段。
2. 更新五線與 Franiya 的來源／AU 雙游標。
3. 更新人物知識、關係、位置、資產與稱呼。
4. 更新普通人、制度、犯罪、文化與經濟後果。
5. 更新本資料夾 `RESUME_CURSOR` 與 `11_正式章節/README.md`。
6. 執行矛盾檢查後才建立 Git checkpoint；未推送成功不得稱遠端已保存。

## 8. 正文完成標準

- 使用者要求「開始寫／繼續」時，交付完整章，不交片段、提綱、`待續` 或「下一次再補」。
- 設定資訊必須經事件、誤判、選擇與代價顯露，不讓人物輪流作世界觀問答。
- 角色說出口的資訊不得超過其知識、信任、風險承受與當下時間。
- 重要事件的反應需自然服務場面；普通生活的笑、停頓、手勢與對話亦可只呈現生活質感，不必強制改變重要決策。
- 原著沒有寫明的過橋不得偽裝成原作事實；可用最小 AU 補橋，但要標記並接受後續修正。
