# 一、正式章節密度固定提高

使用者明確要求：

> **正式正文一章原則上至少消耗約 5 個現有 PREWRITE 事件節點的內容量。**

因此禁止再使用：
> 一個 PREWRITE 節點 = 一個正式正文章節

的低密度施工方式。

正式章節應像一個真正完整的大段故事推進，至少包含：
- 多個事件；
- 多次人物選擇；
- 一個以上局勢變化；
- 至少一輪因果回收或新問題成立；
- 足夠的世界運作、人際互動與場景連續性。

---

# 二、PREWRITE 的「章號」重新定義

現有檔案如：
- `02_第一至第五章_PREWRITE.md`
- `04_第六至第十五章_PREWRITE.md`
- `07_第十六至第二十五章_PREWRITE.md`
- `08_第二十六至第三十五章_PREWRITE.md`

其中原先的「第 X 章」標題，從本 Gate 起優先理解為：

> **第 X 號 PREWRITE 事件節點／施工節點。**

它們仍保留原標題方便搜尋與舊索引兼容，但不再機械對應正式正文章號。

例如：
- PREWRITE 節點 1～5 → 正式第一章的主要內容來源；
- PREWRITE 節點 6～10 → 正式第二章的主要內容來源；
- PREWRITE 節點 11～15 → 正式第三章的主要內容來源；

後續亦類推，但不是死板五等分。若某大型事件自然需要更多篇幅，可一章消耗 6～8 個節點；若某些節點本身極重，也可以經 Gate 判定後拆成上下章，但**不得回到一節點一章的碎片化節奏**。

# 四、章節長度不以固定字數硬切

此 Gate 管的是**內容量與事件密度**，不是機械字數。

因此：
- 不能為了達到某個字數塞水文；
- 也不能因單次輸出方便就在一個事件剛開始時硬切章；
- 一章若需要 1.5 萬、2 萬甚至更多中文字才能完整承接五個事件節點，可以正常寫長；
- 如果平台單次輸出限制需要分批交付，仍視為同一正式章的 Part 1 / Part 2，而不是擅自改成兩章。

固定：
> **事件完成度優先於單次輸出長度。**

---

# 五、正式章節內部節奏

一章包含多個 PREWRITE 節點，不代表用五個小標題硬拼在一起。

應透過：
- 時間自然流動；
- 人物移動；
- 世界公告；
- 危機擴散；
- POV 交錯；
- 同一因果鏈逐步升級

把多個節點融合成一個連續故事。

禁止：
> 「第一節：節點1」→「第二節：節點2」→像五篇短文黏起來。

場景切換可以存在，但每次切換都要服務同一章的局勢推進。

---

# 六、POSTWRITE 密度 Gate

每章寫完額外檢查：
1. 本章實際消耗多少 PREWRITE 節點？
2. 是否至少約 5 個節點的事件量？
3. 若少於 5，是否有單一事件本身達到重大篇章級重量？若沒有，判定過短，需要繼續寫，不得提交為完整章。
4. 是否只完成「一場對話＋一場小戰鬥＋一個公告」就收章？若是，通常密度不足。
5. 是否為了章末鉤子提前切斷一個本應連續完成的事件？若是，優先合併。
6. 是否保留角色生活、人際互動、世界運作與普通人的因果，而不是只快速打勾五個事件？

---

# 八、作者硬規則

> **PREWRITE 是材料箱，不是正式章節編號。**

> **一個正式章應有足夠內容讓讀者真正讀完一段人生與局勢，而不是剛發生一件事就切章。**

> **寧可一章很長，也不要把同一個兩小時內連續危機切成五章薄片。**
