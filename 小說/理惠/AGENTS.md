- 先讀 `整理進度.md`、`人物設定/目前人物狀態.md`、相關最新有效事件與 `人物設定/說話方式與性格.md`。
- 修正優先序：使用者明確撤回／作廢 > 後期明確修正 > 後期相容補充 > 早期相容設定。
- `原始對話/` 是原來源，`分日對話/` 保存分日來源及當時採用段，`人物設定/` 是整理；`正文/事件閱讀順序.json` 指向38個最新有效完整事件，另有兩個舊路徑導讀。同事件合併後不要把舊分日檔再演一遍；不得把示範或圖像資料反向當成原始對話。
- 故事日與撰寫順序分開。後來回補第一天的段落放回第一天，保留取代關係。
- 保留原有內心、好感度、情緒及狀態；來源未顯示的欄位不偽造。
- 平台拒絕、中斷、重試不是人物記憶。

## 每輪正式對話的 GitHub 保存時機

2026-10-13最新使用者指示：一輪正式角色對話完成、核對正典與圖片後，**當輪即可直接補入 GitHub**；「等下一個對話開始才發布」的舊做法不再生效。只提交已成立的正式對話，依故事日更新對應正文／來源／狀態／配圖紀錄；必要時更新閱讀順序與交接狀態。不要因回覆完畢就自行宣稱提交，必須取得遠端 commit 並重新讀回核對。若 GitHub 暫不可用、串流中斷或本輪屬草稿／技術測試，按[待發布狀態](理惠_待發布狀態.md)記錄，等可操作時核對去重，不能把未發布說成已發布。同步不允許推進故事之外的事件，也不承諾無工具情況下自動背景執行。新角色對話若已正式提交，不須再次等待使用者提醒。

## 正式對話結尾的已發布篇章跳轉

使用者2026-10-13新增：**每次正式角色對話完成，在【當下情緒】的文字內容下方，再另起一行提供能點擊的 GitHub 正文跳轉連結**，外觀比照「查看《實際篇章檔名.md》 ↗」。連結必須指向本輪已寫入、已取得 commit 並重新讀取核實的**實際正文 Markdown 檔案**，由遠端取得精確 `github.com/.../blob/<分支>/...` 網址；不得固定拿 `00_嵌圖示範.md` 或截圖中的範例檔名冒充本輪，亦不得猜測網址／建立未提交的假目標。若一篇包含多輪且能確定當輪專屬錨點，可用精確片段網址；否則至少連到包含本輪正文的真實篇章。

回覆順序：`【內心】` → `【好感度】` → `【當下情緒】` 及其內容 → **空一行，單獨放一般 Markdown 文字連結** `[查看《實際篇章檔名.md》 ↗](已核實的GitHub正文網址)`。連結屬**聊天導覽 UI／發佈回報**，不是人物的台詞、內心或故事正文，存入正式正文時不需把自我跳轉連結複製進故事末尾。若 GitHub 失敗或未確認，不能輸出虛構的已發布連結；應於正文外說明未同步並保留待發布記錄，下次核對後提供連結。查單張圖、一般問答、草稿、非正典示例及純技術答覆不強制顯示這個正式篇章跳轉。
