## 正式對話完成當輪的處理方式

1. 確認使用者是要求續寫**正式角色對話**，而非單圖測試、非正典模擬、技術排查、草稿、回補或已作廢版本；先讀最新正式末句及當輪可見輸入。
2. 完成當輪正文後核對首句承接、日期與地點、理惠性格、【內心】【好感度】【當下情緒】，以及按《圖像輸出規則》挑選的相符配圖：可用時優先3張、情節合適可4張以上，素材不足不硬湊。
3. **當輪即可將正式定稿補到 GitHub 的 `小說/理惠/`**；不需等使用者推進下一輪，僅在當前會話具有可用的 GitHub 操作權限時執行。保留原始輸入與回覆、正典採納和圖片引用的出處；視情況更新正文事件、閱讀順序、配圖紀錄、狀態與時間線，避免重覆登錄。
4. 只有在確認遠端 commit 成功、回讀內容與本輪定稿一致後，才回報「已同步」。若工具不可用、串流中斷或內容未定稿，應如實保留待發布資訊並等待可用時核對補件，不可宣稱已完成。
5. 待發布紀錄應包含：來源對話識別或日期、當輪有效正文錨句／摘要、是否已定稿、缺少哪些文件、上次失敗原因、是否已取得遠端 commit。下次處理前先查是否重複發布，確認後更新此檔；不要把純技術訊息寫成角色記憶。

## 當輪保存成功後的回覆跳轉

正式角色對話一輪完成且已取得 GitHub commit、回讀核實新文字確實位於指定篇章，當輪回覆必須在【當下情緒】內容後附上 `[查看《本輪實際篇章檔名.md》 ↗](經核實的GitHub正文網址)`。若不具備可核實的特定定位片段，連到確實包含本輪內容的整篇 Markdown；不要用非正典示範頁或不存在的預定檔名充當成果。

若串流中斷、提交失敗、遠端回讀不符或尚未正式定稿，不可輸出聲稱已發布的跳轉連結；保留待發布依據，並在正文外說明實際狀態。跳轉連結本身是聊天的操作導覽，不能被認作理惠台詞或額外故事事件。
