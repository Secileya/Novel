# P2｜原著證據稽核：SOURCE_NODE 雙向硬門檻

## 2.1 先定位，不能止於搜尋片段

可用人物名、裝備、技能、公會、台詞、任務、地點搜尋定位。

**關鍵詞命中只能標：**

`SOURCE_PROGRESS = KEYWORD_LOCATED`

不得稱完整核對。

## 2.2 哪些一定建立 SOURCE_NODE

至少包括：

- 具名物品、裝備、技能；
- 金錢／收入／價格／產業；
- 排名／首殺／榜單／獎勵；
- 稱號／官職／爵位／權限；
- 任務關鍵物／唯一線索；
- 地點標記／傳送／物流；
- 關係建立／知識與情報轉移；
- 任何後文會再次使用、升級、出售、交換、回收或依賴的要素。

表面是小Boss／小道具也不能跳過；後文是否再利用才決定重要性。

## 2.3 Pass A｜連續局部事件序列

定位後必須連續閱讀前後文，拆出：

`來源/發現 → 取得 → 持有 → 啟用/加工 → 公開 → 出售 → 交付 → 代辦服務 → 返還 → 首次使用`

不適用的步驟可省，但原著跳過的步驟不能自行補。

Pass A 至少回答：

1. 事件怎麼開始；
2. 每一步實際順序；
3. 誰持有什麼；
4. 誰知道什麼；
5. 事件局部明示終態。

完成後才可標：

`SOURCE_PROGRESS = LOCAL_CONTEXT_READ`

## 2.4 Custody Chain｜保管鏈

重要物品／資產固定記：

`來源 → 誰取得 → 誰持有 → 誰啟用或加工 → 是否交付 → 交給誰 → 是否返還 → 後續誰使用`

如果只知道前後狀態，中間交接原文沒寫：

`SOURCE_UNSTATED`
`DO_NOT_NARRATIVIZE_OR_FILL = TRUE`

## 2.5 Knowledge Flow｜資訊流

固定拆：

- 誰知道；
- 知道名稱／位置／效果／機制／完整方法中的哪些層；
- 哪些公開；
- 哪些仍保密；
- 出售的是**資訊／物品／服務**哪一種；
- 哪些只是人物推測；
- 哪些只有作者層知道。

禁止把「持有物品」推成「知道完整機制」，也禁止把「賣取得攻略」和「賣成品／提供加工服務」混成同一件事。

## 2.6 證據四分欄

每個重要斷言只能是：

- `SOURCE_EXPLICIT`：原著明示；
- `SOURCE_UNSTATED`：原著沒寫；
- `REASONABLE_INFERENCE`：前後證據支持但非明示；
- `ADAPTATION_OPTIONAL_BRIDGE`：Franiya線可自行加的橋接。

`SOURCE_UNSTATED` 永遠不能在研究稿、PREWRITE或正文摘要裡偷升格成 `SOURCE_EXPLICIT`。

若正文需要跨越未明示邊，只能在PREWRITE選：

`ADAPTATION_OPTIONAL_BRIDGE = MINIMAL_COMPATIBLE_BRIDGE`

只補足前後狀態連續所需的最少行為，不替角色補完整自述、額外知識、額外交付或額外權限。

## 2.7 Pass B｜向後搜尋再利用，再反查源頭

完成 Pass A 後，必須針對該物／事件向後搜尋：

1. 第一次再使用；
2. 第一個真正下游依賴；
3. 重要長期再利用／升級／交易；
4. 經濟、權限、關係、情報後果；
5. 最晚處理窗口。

然後反向檢查：後續用途是否偷偷依賴一個原始事件中其實沒寫的「交付／知情／加工／保管」邊。

## 2.8 六項驗收 Gate

每個重要 SOURCE_NODE 都要：

- `LOCAL_SEQUENCE_PASS = PASS`
- `CUSTODY_CHAIN_PASS = PASS`
- `KNOWLEDGE_BOUNDARY_PASS = PASS`
- `DOWNSTREAM_REUSE_PASS = PASS`
- `UNSTATED_EDGE_MARKED = PASS`
- `FORMAL_CONFLICT_CHECK_PASS = PASS`

全部通過才可：

`SOURCE_NODE_BIDIRECTIONAL_CLOSURE_GATE = PASS`
`SOURCE_PROGRESS = BIDIRECTIONAL_AUDIT_COMPLETE`

少一項就：

`SOURCE_NODE_AUDIT = INCOMPLETE`

並留下精確 resume cursor。

### 禁止事項

- 禁止未完成雙 Pass 就說「已仔細檢查／完整抓取／閉環」。
- 禁止 SOURCE_NODE 未六Gate全PASS就建立原文審計 `READY_NOW`。
- 禁止用模型印象填 SOURCE_UNSTATED。
- 禁止看到後來有人持有某物，就倒填「前面某人一定親手交給他並完整說明」。

## 2.9 Formal Conflict Check

雙向稽核後反查：

- 正式正文；
- Current State；
- 知識矩陣；
- 正式事件佇列；
- 仍有效POSTWRITE／同步差分／索引。

若正式章與原文邊界衝突，而本輪是原文審計端：

- **不直接改正式章**；
- 六Gate全PASS後建立／更新 `READY_NOW`；
- 寫明正文章節、原文證據、SOURCE_UNSTATED、最小修復邊界、禁止補寫內容；
- owner=`芙蘭 信仰正文`。

若只是本線新增選擇，且已明標 `ADAPTATION_OPTIONAL_BRIDGE`、不冒充原著，也不破壞長線，則不是原文衝突。

# P3｜Franiya 差分重算

核心公式：

**本線現況 = 原著仍可成立的世界／制度基線 + Franiya與本線已固定條件 − 沈雲專屬前提 + 新因果自然後果。**

## 3.0 高保真骨架

優先保留：

- 世界內時間錨；
- 重要事件節點；
- 世界規則／制度因果；
- 重要人物DNA；
- 物品／經濟／權限／關係的長期功能。

只移除真正不能轉移的：

- 重生情報；
- 沈雲私人舊仇；
- 只能由原戀愛關係成立的選擇；
- 沈雲專屬未來物資／人脈。

若原觸發動機消失，先找本線人物、勢力、利益、公開戰績、地點、任務或制度能否建立新的自然觸發；不能一看到動機不同就把整條事件和後續資產一起刪掉。

## 3.1 Franiya 強度與角色殼

- 她沒有沈雲重生攻略。
- 她的戰鬥經驗、感知、即時建模、身體控制、武器理解遠高於同期玩家。
- 被限制的是遊戲角色輸出端，不是戰鬥理解端。
- 世界級玩家仍要保持真實專業性，但只靠玩家技術本身不能構成Franiya真正難題；真正壓力來自數值／裝備／資格／任務／地形／多目標／資訊黑箱／制度後果。
- 原著沈雲的技術苦戰不能機械移植。
- 差距擴大靠Franiya更強，不靠把別人寫笨。

## 3.2 事件節點保留，不保留沈雲數字上限

保留事件功能與因果，不把沈雲當時的擊殺數、耗時、受傷量當Franiya上限。只要角色殼允許，結果可更快、更乾淨、更大，世界反應也要同比放大。

千人圍堵等事件必須按「誰實際選擇參戰」重算；不採為了善良化而機械放人。

## 3.3 事件資格可有限等價重算

先分：

1. 世界硬機制：原則不改；
2. 事件資格／敘事門檻：可保留原稀有度與功能做有限等價重算；
3. 沈雲專屬條件：移除或重建。

任何改門檻都要在PREWRITE寫：`原著條件 → 本線條件 → 理由`。

## 3.4 等級時間

- 已固定「Lv8為既有早期硬錨」保留，不回頭重寫舊章。
- Lv8之後等級按本線實際EXP／任務／擊殺自然推進，不為等原著事件無理由卡級。
- 原著世界時間錨與Franiya等級解耦；到同一事件時可以比沈雲原線更高。

## 3.5 技術公開≠被看穿

公開首殺／錄像只代表外界有素材。大規模公開PvP後才適合讓頂尖觀察者逐步摸到可觀測輪廓；仍不能看穿她完整能力。

## 3.6 假動作

假動作是工具，不是固定表演。只有能騙技能、重心、視線、路線、資源或製造多線同步時才用；零無效動作與有效假動作不衝突。

## 3.7 原著人物延後登場

「原時點沒觸發」≠「人物永久刪除」。重要人物進延後追蹤，每次PREWRITE掃第一個自然載入窗口：Boss、裝備、交易、論壇、公會、現實組織、既有人際、地點、任務交會。

# P5｜篇章與章節規劃

## 5.1 長章制

- 不固定「我方1章＝原著N章」。
- 一章可以承載多個同一連續時間窗內的完整事件節點。
- 不為章長硬斷；在小弧線／關係轉折／局勢變化完成後斷。
- 增量來自事件、人物、世界自主線、規則與後效，不靠重複心理／移動灌水。
- 原著重要事件進入當前窗口後優先場景化，不能一句報告帶過。
- 世界不等Franiya到場才運轉；公會、玩家、現實人物可在鏡頭外自主推進。

## 5.2 時間跳躍 Gate

跨半日／跨日前回答：

1. 當前世界時間的原著事件有哪些；
2. 哪些完成／正在發生／已可成立；
3. 鏡頭外重要人物進度；
4. 是否因主角不在場錯漏事件；
5. 本章還能承載什麼；
6. 未寫事件是否都有重檢條件。

全部成立才可：

`CURRENT_WINDOW_EVENT_SATURATION = PASS`
`TIME_SKIP_GATE = PASS`

## 5.3 原創事件收束 Gate

原創支線正式展開前至少核定：

- `ARC_END_STATE`
- `ARC_PAYOFF`
- `TERMINAL_DISCOVERY`
- `MAX_ESCALATION`
- `EXIT_CONDITION`
- `DOWNSTREAM_HANDOFF`

禁止「線索A→B→C→D」無上限接龍；每個新線索要縮小不確定範圍。

## 5.4 單章 PREWRITE

至少列：

- 時間／地點／POV；
- 章首狀態；
- 核心看點；
- 原著錨點；
- 遊戲／現實時間；
- 原著人物延後登場檢查；
- 本章命中的正式事件；
- 本章消耗的 SOURCE_NODE 與六Gate狀態；
- 所有 SOURCE_UNSTATED 與最小相容 bridge；
- Franiya／其他人物知道與不知道什麼；
- 角色殼／力量尺度；
- 至少一條世界自主運作線；
- 章末不可逆改變；
- 下一章自然入口。
