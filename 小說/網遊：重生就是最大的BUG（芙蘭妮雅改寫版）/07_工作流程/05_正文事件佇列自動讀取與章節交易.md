# 正文事件佇列自動讀取與章節交易

> 狀態：ACTIVE / REQUIRED  
> 建立：2026-09-28  
> 適用：`owner=芙蘭 信仰正文` 的正式續寫、回修、POSTWRITE與連續性同步。  
> 上游證據門檻：`07_工作流程/06_SOURCE_NODE雙向稽核與證據邊界.md`。

## 一、每次正文接手的固定啟動順序

1. **先同步 GitHub `main`**，不得沿用舊對話記住的 HEAD。
2. 動態掃描 `01_章節/`，以實際檔名與正文確認**最高正式章**；交接、索引、PREWRITE裡的固定章號都只能作提示。
3. 讀最小有效包，不全庫載入：
   - `00_專案交接.md`
   - `07_工作流程/00_新對話長期主提示詞.md`
   - `07_工作流程/06_SOURCE_NODE雙向稽核與證據邊界.md`
   - 本檔
   - `04_連續性與索引/01_當前狀態快照.md`
   - `04_連續性與索引/06_章節索引.md`與仍有效的最新增量索引
   - `04_連續性與索引/08_原著事件待處理佇列.md`
   - 最高正式章全文；需要銜接才補前一章章末
   - 本章對應的最近 POSTWRITE／同步差分
4. 再讀事件佇列中 `owner=芙蘭 信仰正文` 且符合下列任一條件的項目：
   - `status=READY_NOW`
   - `status=READY`
   - `status=ACKED` 且另標 `CURRENT_WINDOW_ACTIVE`
   - `status=DEFERRED_WITH_TRIGGER` 且觸發條件已成立
5. 若本章涉及原著事件、物品、順位、人物或規則，精準讀對應 SOURCE_CANON／原文證據；涉及重要 SOURCE_NODE 時，先確認其六項 SOURCE Gate，不為了「順便」擴大搜索範圍。

## 二、SOURCE_NODE 是 READY_NOW 的上游硬門檻

原文審計端不得只因找到一個關鍵詞或後續用途，就把問題送進正文佇列。

重要 SOURCE_NODE 必須同輪完成 Pass A＋Pass B，且六項全部 PASS：

- `LOCAL_SEQUENCE_PASS`
- `CUSTODY_CHAIN_PASS`
- `KNOWLEDGE_BOUNDARY_PASS`
- `DOWNSTREAM_REUSE_PASS`
- `UNSTATED_EDGE_MARKED`
- `FORMAL_CONFLICT_CHECK_PASS`

只有：

`SOURCE_NODE_BIDIRECTIONAL_CLOSURE_GATE = PASS`

才可把衍生正文問題標成 `READY_NOW`。

否則只能：

`SOURCE_NODE_AUDIT = INCOMPLETE`

並留下精確 resume cursor；正文端不得把未完成審計的猜測當作硬母本。

### SOURCE_UNSTATED 正文邊界

若 SOURCE_NODE 標有：

`SOURCE_UNSTATED + DO_NOT_NARRATIVIZE_OR_FILL = TRUE`

正文端不得自行寫成「原著角色其實完整解釋過／交付過／操作過」。若本線為連續性需要跨過這條空白，只能在 PREWRITE 建立：

`ADAPTATION_OPTIONAL_BRIDGE = MINIMAL_COMPATIBLE_BRIDGE`

橋接只補足前後已知狀態最少所需行為，不能順手附贈額外情報、完整自述、額外物品轉移或新權限。

## 三、事件 ACK 是正文前置，不是事後備忘

正文端讀到可執行事件後，必須在佇列回寫其中一種結果：

- `ACKED`：已讀並納入本章／本次回修決策，但尚未完成整合。
- `INTEGRATED`：正文與所有必要下游同步均已完成，並填入執行 commit。
- `DEFERRED_WITH_TRIGGER`：本章不處理，但必須寫出**精確重新觸發條件**；不得只寫「之後再說」。
- `BLOCKED_NEEDS_USER`：確實存在高影響、無法由既有權威判定的分歧，才可使用。

`READY_NOW` 不得被正文端看過後保持無 ACK 狀態繼續往下寫。

### CURRENT_WINDOW_ACTIVE 硬規則

`CURRENT_WINDOW_ACTIVE` 不是新的 status，而是「經雙向原文稽核確認，敘事功能硬窗口已經到達」的硬標記。必須有已完成 SOURCE_NODE 支持，不能只由「角色現在剛好在某地」推演出來。

事件若真正標成 `CURRENT_WINDOW_ACTIVE` 且尚未整合，下一次 PREWRITE 必須二選一：

1. 寫出當章／窗口截止前的**自然合法取得與落地方案**；或
2. 若當章因果無法自然承接，先建立**精確最小回修方案**，再進正文。

禁止把 `CURRENT_WINDOW_ACTIVE` 降回泛化 `EVERY_CHAPTER_RECHECK` 後直接寫過真正硬窗口。

**傳送珠不是目前的 CURRENT_WINDOW_ACTIVE 案例。**雙向回歸已確認：原著第一次星辰深淵探索後可以先離開；第107章是沈雲後來靠【定位傳送機】重新回到地下森林後才用【傳送珠】建立標記。Franiya目前第48章尚未錯過。正確硬截止見 `EVT-ASSET-TRANSFER-ORB-001`：`BEFORE_CH107_EQUIVALENT_FIXED_STAR_ABYSS_LOGISTICS_OR_FIRST_REQUIRED_TRANSFER_ORB_MARK`。

## 四、章節交易完整性

一章或一次正式回修只有在下列項目**全部完成**後才算交易完成：

1. 正文檔已寫入並通過本輪 QA。
2. POSTWRITE 已完成。
3. 同步差分／章節索引已更新。
4. `04_連續性與索引/01_當前狀態快照.md` 已更新到新狀態。
5. 本章命中的事件佇列已回寫 ACK 結果；已整合者填入執行 commit。
6. 本章消耗的重要 SOURCE_NODE 已有 `SOURCE_NODE_BIDIRECTIONAL_CLOSURE_GATE = PASS`；若仍 `INCOMPLETE`，正文不得越過未驗證邊界。
7. 本章跨過任何 `SOURCE_UNSTATED` 時，PREWRITE已記錄最小相容 bridge，且沒有把 bridge 冒充原著明示。
8. 所有本輪 GitHub 修改已 commit 到 `main`，並做最終 HEAD／可達性驗證。

**少任何一項，都不得開始下一章。**

固定標記：
- `CHAPTER_TRANSACTION_REQUIRES_BODY = TRUE`
- `CHAPTER_TRANSACTION_REQUIRES_POSTWRITE = TRUE`
- `CHAPTER_TRANSACTION_REQUIRES_SYNC_DIFF = TRUE`
- `CHAPTER_TRANSACTION_REQUIRES_CURRENT_STATE = TRUE`
- `CHAPTER_TRANSACTION_REQUIRES_EVENT_ACK = TRUE`
- `CHAPTER_TRANSACTION_REQUIRES_SOURCE_NODE_GATE = TRUE`
- `SOURCE_UNSTATED_REQUIRES_MINIMAL_BRIDGE = TRUE`
- `NEXT_CHAPTER_BEFORE_TRANSACTION_COMPLETE = FORBIDDEN`

## 五、原著事件四分類

事件佇列採四種改寫分類：

- **A｜必須重建主線鑰匙**：原著後續大量因果依賴此事件功能；不能只刪掉，要依 Franiya 本線重新建立等價因果。
- **B｜不得幽靈繼承資產**：原著主角因特定擊殺、任務、關係或偶然取得的物品／權限，Franiya未走同一因果就不能自動持有。
- **C｜必須重算結果**：事件功能可保留，但名次、勝負、掉落、人物、收益、死亡或公開後果依本線重算；若使用者已明確鎖定某個結果，該結果本身不再重算。
- **D｜可換來源保留功能**：後續世界線確實需要某項功能時，可用新合法來源取得；若佇列另註「必須取得本體」，D只代表來源可換，不代表可用等價物取代。

同一事件可有主分類與附帶警告，但正式欄位只填一個主分類。

## 六、原著事件審計發現錯誤時

- 若問題只在流程、索引、佇列、狀態檔，且答案已可確定：**當輪立即修正**，不得完整找完後留到下一輪。
- 若問題已落入正式正文，而本輪是「原文事件審計／不得改正式章」模式：先完成 SOURCE_NODE 雙 Pass＋六 Gate；通過後建立或升級為 `READY_NOW`，精確寫出章節、SOURCE_EXPLICIT、SOURCE_UNSTATED、錯誤因果、最小修復邊界與禁止補寫內容；不得偷偷改章。
- 若只是本線新增內容，而且明確被標為 `ADAPTATION_OPTIONAL_BRIDGE` 且沒有冒充原著明示，不必機械判定成正文錯誤。
- 若本輪明確授權正式回修：先修正文，再同步 POSTWRITE、Current State、索引與事件 ACK。

## 七、並行寫入與收束 checkpoint

- 每次寫同一路徑前重新抓最新 blob SHA。
- 連續多檔寫入時不得假設 HEAD 不會被其他對話推進。
- 接近上下文／時間上限時，停止擴大搜尋：先把已完成批次寫入、自檢、commit 到 `main`。
- 已開啟但沒完成雙 Pass 的 SOURCE_NODE 必須標 `INCOMPLETE`、留下精確 `RESUME_CURSOR`；不得用「已完整核對」收尾。
- checkpoint 不得以「已找到問題、下輪再改」收尾。

## 八、最終自檢

收尾至少確認：

- 正式佇列只有一個 active path：`04_連續性與索引/08_原著事件待處理佇列.md`。
- 交接檔只保留當前必要控制資訊、下一章前必讀與正式佇列連結，不建立第二套事件真值。
- 新增／升級為 `READY_NOW` 的原文審計事件都能指回一個六 Gate 全 PASS 的 SOURCE_NODE。
- `SOURCE_UNSTATED` 邊已標記，沒有被流程／PREWRITE／正文摘要偷升格成 SOURCE_EXPLICIT。
- `READY_NOW / CURRENT_WINDOW_ACTIVE` 事件均有 EVENT_ID、原文證據、本線狀態、分類、禁止誤寫、正文動作、觸發點、owner、status、ACK、執行commit。
- 真正的 `CURRENT_WINDOW_ACTIVE` 若尚未整合，下一個 PREWRITE 必須已有合法落地或精確最小回修方案。
- 最後讀取 `main` HEAD；若 HEAD 已前進，確認本輪最後相關 commit 仍在祖先鏈上。
