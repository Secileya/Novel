# 原著事件捕捉與反向歸屬流程

> 建立日期：2026-09-29
>
> 性質：SOURCE_CAPTURE_WORKFLOW / MANDATORY
>
> 第一手來源：使用者提供的完整原著 TXT《网游：重生就是最大的BUG - 刘巴库》。GitHub 既有捕捉檔、差分檔、舊反向稽核只作索引與對照，不得取代第一手原文。

## 一、目的

本流程用來修正早期「逐章摘要抓主事件」造成的系統性漏項。

原著捕捉的目標不是只回答「這章發生了什麼」，而是同時保存：

1. 章內事件的真實先後順序；
2. 人物在事件前後的狀態變化；
3. 任務、技能、裝備、道具、貨幣與權限的完整面板／限制；
4. 所有重要物品的來源、持有人、轉移、掉落、交易與後續用途；
5. 人物關係與誰知道什麼；
6. 論壇、公告、直播、媒體與組織內部的信息傳播鏈；
7. NPC、神明、公會、國家、現實異能與遊戲世界的制度設定；
8. 後文對前文物件／規則／人物的補充；
9. 原著自身的數值、稱呼、版本或敘述矛盾；
10. 沈雲專屬前世因果與可保留世界硬設定的分流。

核心原則：**不能因為原文沒有一句話直接寫「A持有X」，就把仍可由職業、數量、掉落總結、後續清點唯一或部分反推出的情報整批降成未知。**

# 二、每30章的強制五Pass

## Pass A｜逐章事件捕捉

每章至少檢查：

- 事件順序；
- 地點／時間；
- 新人物與既有人物再出場；
- 等級、職業、種族、身份、官職、稱號；
- 任務接取／變更／完成；
- 技能習得／使用／冷卻／限制；
- 裝備、道具、材料、金錢的取得與消耗；
- 戰鬥規則與傷害／控制／掉落判定；
- 公開公告、論壇、直播、新聞、群體反應；
- 人物當下知情與作者層真相。

不得只留「主事件」。小事件若會改變資產、情報、關係、規則或後續因果，同樣必須記錄。

## Pass B｜物品／技能／任務反向歸屬

30章順讀完成後，把本段出現的每一個重要名詞反向搜尋一次，至少包括：

- 裝備；
- 特殊道具；
- 技能；
- 稱號；
- 任務；
- 任務獎勵；
- 鑰匙／卷軸／徽章／材料；
- 特殊貨幣或權限。

每個資產都建立：

`首次出現 → 原始來源 → 原持有人 → 取得條件 → 轉移／交易／掉落 → 當前持有人 → 後續首次使用／補面板 → 長線用途`

若同一件物品在本段後方才補出來源、效果或真正持有人，必須回填前文捕捉，不得只記在後章。

## Pass C｜跨章關聯反推

逐章文字沒有直接點名時，必須檢查是否能由多章資訊縮小答案。

允許的反推證據包括：

- 職業與裝備使用要求；
- 人數與掉落數量；
- 「全部掉落／只有某人沒掉」等總結句；
- 角色死亡順序與掉落包；
- 後續背包／裝備清點；
- 交易前後物品是否仍在；
- 任務獎勵與後續首次使用；
- 排名獎勵階梯；
- 公開榜單與匿名持有人資料。

證據層級固定分三種：

### `SOURCE_EXPLICIT`
原文直接點名。

### `SOURCE_DERIVED`
原文沒有單句直接點名，但多個已明示事實能形成必然或可證明的縮小集合。

例如原著第97～100章：
- 糖度過高、四海縱橫＝法師；
- 青絲縛劍、西江月、半夢半醒＝戰士；
- 五人的暗金獎勵全部掉落；
- 沈雲清點為三件戰士暗金＋兩件法師暗金。

因此可以確定：
- 【深海水晶球】【火焰法杖】來源池＝糖度過高／四海縱橫，一人一件；
- 【貪狼鎧甲】【貪狼戰盔】【貪狼腿甲】來源池＝青絲縛劍／西江月／半夢半醒，一人一件；
- 只有池內逐件對人的最後一層仍未明示。

這種資訊不得錯寫成「五人九件完全無法分辨」。

### `SOURCE_UNSTATED`
只有在完成以下四步後仍無法再縮小，才准使用：
1. 回讀當章完整正文；
2. 回讀前後相鄰章；
3. 全文搜尋物品名／人物名／技能名；
4. 做職業、數量、掉落、交易、後續清點的跨章反推。

`SOURCE_UNSTATED` 是最後結論，不是省略檢索的快速標籤。

## Pass D｜資訊傳播與知情邊界

每個重要情報至少回答：

- 最初誰知道；
- 誰親眼看到；
- 誰只看到結果；
- 是否上論壇／公告／直播／新聞；
- 是否有人誤判；
- 誤判如何擴散；
- 後續由什麼新證據修正；
- Franiya改寫線是否具備同樣資訊來源。

不得用作者全知替人物補情報。

## Pass E｜30章反向閉環稽核

完成30章後，不可直接跳下一組。必須再次由結果往前掃：

1. 本段所有重要物品現在在哪；
2. 每件物品最初從哪來；
3. 是否有消耗卻沒記來源；
4. 是否有後文使用卻沒記取得；
5. 是否有角色突然知道前文未建立的資訊；
6. 是否有論壇／公告結果但漏掉公開動作；
7. 是否有後章補面板但前章沒有回填；
8. 是否存在原著矛盾而被不小心統一；
9. 是否把可反推情報誤標成SOURCE_UNSTATED；
10. 是否把沈雲專屬前世因果錯當世界硬規則。

只有上述閉環完成，該30章才可標記 `REVERSE_ATTRIBUTION_SCAN_PASS`。

# 三、資產追蹤最小欄位

每個重要資產至少記錄：

- 名稱；
- 類型／品階；
- 首次出現章；
- 原始來源；
- 取得條件；
- 首位已知持有人；
- 轉移方式；
- 當前持有人；
- 已知消耗；
- 後續補面板章；
- 後續用途；
- 證據等級：EXPLICIT／DERIVED／UNSTATED；
- Franiya線狀態：已取得／未取得／來源待重建／不得直接移植。

對「人群掉落池」不得只寫群體名稱。只要能縮成法師池、戰士池、特定四人池、某兩人池，就必須縮到當前證據允許的最小集合。

掃描發現新漏項時：
- 優先建立／更新對應反向稽核覆蓋檔；
- 若舊SOURCE_NODE因錯誤的SOURCE_UNSTATED而建立過度模糊保管池，同步修正SOURCE_NODE；
- 不因研究層修正自動改寫已完成正式正文，除非漏項已造成正式Canon衝突，再另開正式修正流程。
