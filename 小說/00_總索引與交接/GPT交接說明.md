# GPT 接手規範

## 必讀

- 不把作者後台資訊直接塞入角色視角。
- 明確作廢／撤回的內容優先於舊稿；後期明確修正優先於早期版本。
- 「續寫」不是「重寫」。除非使用者要求，從最新有效斷點接續。
- 正史、非正史分支與不同世界線永久分離，只有使用者明確採納時才可合併。
- 角色外貌、能力、關係與稱謂，先查角色總檔及專案內設定，不憑印象補完。
- 引用外部作品、遊戲層級或 NPC 時，先核對來源，再區分原設定與二創改編。

## 每次開始工作

1. 讀 `CATALOG.md`。
2. 鎖定單一專案。
3. 讀該專案 `PROJECT_HANDOFF.md`。
4. 讀其指定的世界基準、角色總檔、章節索引與最新正文。
5. 先說明採用的正史斷點，再寫作。

### 莉月企劃特別規則

- `projects/apocalypse-liyue/` 是同一企劃容器，不代表其中三條世界線互通。
- 先選 `mainline`、`late-era-72-years` 或 `high-martial-reset`，只讀該線正文與索引。
- `source-research` 是共同題材底稿；可支撐構思，但不可把參考作品事件或早期草案直接寫成莉月正典。

## 每次完成工作

1. 保存完整章節，不留片段式「待續」。
2. 同步章節索引／連續性台帳。
3. 記錄新設定、伏筆、角色知情範圍及下一章入口。
4. 不覆蓋來源原稿；需要重寫時另存新版本並標示取代關係。
