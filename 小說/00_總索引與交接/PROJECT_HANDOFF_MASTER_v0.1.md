# 小說專案總交接入口

> 本檔是小說 repo 的總接手入口。任何新對話、新模型或隔很久後重新接手小說工作時，先讀本檔，再依指示進入目標專案／世界線。

## 1. 核心原則

GitHub 是小說專案的長期權威記憶。聊天記憶、模型 Memory、摘要與臨時筆記只作導航，不得取代正文與正式設定。

權威優先順序：

1. 最新有效正文
2. 後來明確修正／作廢／撤回聲明
3. 穩定設定檔
4. 連續性、狀態、索引、台帳等工作記憶
5. 聊天記憶與模型 Memory

若衝突，依此順序處理；工作記憶若與正文衝突，先以正文為準，再修正工作記憶。

## 2. 接手前必讀

1. `小說/00_總索引與交接/NOVEL_WORKFLOW_PROTOCOL.md`
2. `小說/00_總索引與交接/小說總目錄.md`
3. 使用者指定專案／世界線的 `00_專案交接.md` 或既有對等交接檔
4. 該線「當前狀態／未完成因果／角色知識／修正禁用／章節索引」
5. 最近 2–5 章正文
6. 本次真正涉及的角色、能力、世界規則與早期事件原文

不得只憑「我記得之前讀過」直接續寫。

## 3. 目前特別建立持續工作記憶的分支

### 都市世界觀（正史與分支）／非正史分支／合聲線

入口：

`小說/都市世界觀（正史與分支）/05_非正史分支/01_合聲線/00_專案交接.md`

該線已建立獨立的當前狀態、未完成因果、角色知識矩陣、修正禁用、交易資產台帳與章節續寫索引。

## 4. 世界線隔離

正史、非正史分支與不同作品永久分離。兄弟分支可作寫法／能力表現參考，但其中已發生事件、角色知情、關係進度、取得物件與時間線結果，除非目前世界線正文獨立建立，否則一律視為未發生。

## 5. Checkpoint 原則

「正典 checkpoint」只代表：某一 commit 時，正文與該線工作記憶已完成同步。

分支交接檔應保存：
- checkpoint commit SHA
- 最新正文
- 狀態資料同步到哪一章
- 下一自然入口
- 尚未同步項目

若 GitHub HEAD 晚於 checkpoint，先查看其後 commits，判斷是否只有交接指標／文檔更新，或正文已前進。

## 6. 完成工作後

每完成一章或一批正式正文：
- 寫入正文
- 更新當前狀態
- 更新未完成因果
- 更新角色知識矩陣
- 有永久設定變動時更新設定
- 有作廢內容時更新修正禁用
- 更新章節索引
- 有交易／物件／契約變動時更新台帳
- commit
- 再把已同步 commit SHA 寫入該線交接檔

詳細流程以 `NOVEL_WORKFLOW_PROTOCOL.md` 為準。
