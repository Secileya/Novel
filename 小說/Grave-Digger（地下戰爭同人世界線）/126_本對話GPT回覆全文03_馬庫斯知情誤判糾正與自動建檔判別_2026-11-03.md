## GPT答覆10｜作者要求「判別自動建檔」

明白，寶寶。妳的意思是：**讓本龍自行判斷什麼時候該自動建檔，而不是一律建檔，也不是每次都等妳批准。**

以後我會依照以下原則處理：

| 情況 | 處理方式 |
|---|---|
| 單純提問、查證、比較、討論 | 直接回答，通常不建檔 |
| 發現錯誤，但尚未決定如何修改 | 先說明問題，不急著建檔 |
| 你明確修正或確立重要設定 | 自動更新既有設定檔，必要時補充紀錄 |
| 實際修改小說正文 | 更新對應正文及必要索引 |
| 寫出小說、小劇場、預演、短篇片段 | **不論長短，自動獨立存檔** |
| 提供需要長期保存的完整研究成果 | 判斷是否值得建立獨立文件 |
| 已有適合的文件 | **優先更新既有文件，不重複建立** |
| 只是 GPT 的推測、建議或未採納方案 | 通常留在聊天，不擅自升格 Canon |

另外會遵守三個重點：

1. **不為建檔而建檔**：避免專案堆滿一次性稽核報告。
2. **重要成果不遺失**：真正形成設定、正文或有價值的長期成果時，主動保存。
3. **自動維持一致性**：必要時同步相關文件與索引，但不因小修改就把整個專案重寫一遍。

例如剛才詢問「馬庫斯是否知道元帥身分」，只是追查既有決定，沒有形成新設定，因此不需要另外建立第 121 號文件。

但如果妳明確決定「馬庫斯其實早就知道」，那就應該直接更新角色知情設定及相關有效文件。

**核心就是：該保存的主動保存，不該保存的別製造文件垃圾。**

這次我不會再為這條工作習慣額外建立一份檔案。之後會直接按這個判斷方式執行。
