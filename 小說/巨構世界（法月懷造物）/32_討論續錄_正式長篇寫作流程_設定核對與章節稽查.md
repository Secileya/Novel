## 1. 基本立場：多份設定不是裝飾品，不能只憑聊天印象寫

- **必須真的查閱 GitHub 原檔**：不能把「有一份總導覽」「我有記憶」「先前總結寫過」當作「已讀完整設定」。文件越多，越需要真正索引、讀取、定位來源及版本，不能忽略以前辛苦累積的世界尺度、角色 DNA、情感結構、機制細節、歷史與否定條件。
- **不必把所有設定塞進每一章**：不登場不等於無效。涉及到某個角色、科技、社會、地區、特殊物件、長期伏筆時，必須遵照相應有效內容；沒涉及的資訊可以暫時留在作者層，但不能被推翻或忘掉。
- **不得使用舊版本覆蓋新修正**：同一檔案不同段落可能保存歷史和最新說法。正式 Canon、後出使用者明確修正、待決候選、助手試寫必須區分；新使用者明確確認優先於舊助手推論。若正式文件尚未同步修訂，先遵照新使用者要求擬寫，不能自行偷偷覆寫正式檔。
- **不自行填死尚未決定之事**：例如巨構外殼完整幾何、特殊槍的核心原理、實際模組數、女主規則作用機制、男主復歸地點與物品去向、世界常規復活方式、最終敵人身分、真正開篇城市與時間，不能以「看起來合理」偽裝成既定設定。

## 3. 啟動正式長篇前：做一次全量資料建檔

正式第 1 章動筆前的作者工作：

**A｜全量資料盤點。**以 00 最新導覽為起點，逐份查閱全部正式世界檔與討論續錄，包含較早被否定的歷史版本、後續確認與圖片參考用途；必要時核對跨檔來源。對不同角色、地圖、科技、社會與敘事規則留可追蹤出處。

**B｜有效設定表。**每條記「精確內容／原檔及段落／現行狀態／後出修正／適用時段或人物／可能衝突／相關已發生正文」：

| 狀態 | 定義 |
|---|---|
| 正式 Canon | 已寫入正式設定及未被明確後出修正取代的內容 |
| 使用者明確方向 | 使用者親自確認，雖未同步入正式檔，創作時仍應優先遵照 |
| 有效候選 | 允許試寫，但不可宣稱已定案的世界事實 |
| 未決 | 不能替使用者擅自定案，遇到必要決策須確認或明確保留 |
| 歷史／作廢 | 只用於追查脈絡，不得倒灌回正式故事 |

**C｜作者層主線基礎。**保留使用者已確認的「諾亞與艾莉維亞想登真正最高層；男主知道原裝武器不完整；逐步取得真正能提高輸出與新形態的模組／能源；與高階前文明或頂尖勢力對抗、重要敵人與最終敵人、真正登頂，之後世界和故事仍可繼續」。具體模組數、最終敵人、上層幾何等仍待規劃，不編造成已定。

**D｜未決與伏筆兩張獨立台帳。**未決表追蹤尚待決定機制；伏筆表按 31 文件記錄已知真相、前置條件、埋設位置、人物情報、預計回收窗口、事件界線。不能把所有普通生活強行解釋成主線伏筆。

**E｜初篇地圖與人物狀態。**不必一次畫完巨構宇宙，但首篇涉及的多出口地理、當地道路、城市生產、貨幣、社會利益、居民生活、人物相遇與登場前背景，必須提前有真實因果與自走時間表。

正式正文存放時要**與討論試寫明確分區**。未經使用者確認的試寫不得列為已發生章節。

## 4. 開始新事件之前：先照第 31 份建立事件骨架

每個單獨事件至少掌握：

- 發生原因、人物個別動機、與主角沒有關係也照樣會運作的社會／生態因果。
- 事件起點、真正的衝突、各勢力已知情報、關鍵選擇、主要轉折、高潮、**預計怎樣結尾、什麼算結案**。
- 路線是否實際存在、開通條件、誰可以使用、出行距離與回程成本；取得新武器模組是否真的提高火力／功能，是否影響其他勢力／商路。
- 本篇需要回答哪些問題；哪些後果能自然延續；哪些是有作者層規劃的跨篇伏筆，不能用一句「更大的謎」取代本篇收束。
- 若人物臨場選擇使事件方向合理改變，可以調整大綱，**但必須同步修正因果鏈和預計收束條件**，不能每章臨時無限加幕後。

**事件骨架不等於僵硬配額**：不鎖每章幾場戰鬥、幾個笑點、幾次臉紅，篇幅由人物、社會和事件實際重量決定。

## 5. 每章正文啟動前：強制實讀流程

**步驟一｜最新版本**：先讀 00 最新索引及這章直接相關的後續修正，尤其可能在另一個對話已更新 GitHub 的 30、31、32+。**不得只用較早回合的個人摘要。**

**步驟二｜前文連續性**：重讀上一章的**正式全文**、本篇近期已發生的直接相關場景；重要老人物／伏筆重新登場時，回查幾十章前**原章**而非靠模糊回憶。

**步驟三｜事件方向**：讀本篇作者層大綱、進度及伏筆台帳，知道目前是什麼階段，本章能回答、排除或推進哪個問題，以及當前事件的結尾仍指向何處。

**步驟四｜真正讀相關設定**：依場景重新開原檔的精確段落。例：
- 新地區：01、02、03、04、05、11、相關群落／貨幣／地圖候選；
- 超級前文明與男主武器：06、11、13、18、24、25、26、28，並對照後出否決；
- 諾亞×艾莉維亞：15、17、20、21、23、27、28、29、30，尤其 30 第七八節；
- Celeste 登場：06、11、17、26、27、28，必要時家庭總檔核對法月懷母女關係；
- 血腥／道德／異質生命：04、05、21、22、23 及具體當地社會設定；
- Path of Pain 式 Celeste 區域：26、28 與日後該地域的正式地理和回憶／模組設計。

**步驟五｜本章起點狀態**：確認故事內日期、各人在何處、誰持有哪些裝備／模組／錢／貨物、傷勢、知識和聯絡方式、是否能搭乘該交通工具、復歸與回程時間、目前戀愛階段及已發生的約定。

**步驟六｜正式下筆**：若本章必要細節仍是未決，**不能假裝既定**；可以在明示試寫前提下測試，或就重大必要選擇請使用者決定。不得改寫角色性格來替劇情硬套效果。

**頻率區分**：長篇啟動時全量閱讀；每個大篇章開始擴大覆核資料；每章至少讀最新索引、前章正式全文、作者事件檔和本章真相關原檔；隔很久重登場的人物、武器模組、重要地點，必須回看其最初建立和正式登場全文。**不是每章機械貼三十份檔案，而是保證相關細節真的使用。**

## 7. 每章寫完後：先做四輪稽查再交稿

**第一輪：設定準確。**逐個核對本章涉及的能力、科技、歷史、地理、稱呼、關係和現行修正；不能拿被否定的 24 初期槍模式當完整頂尖武器，也不能把候選折索集市當既定地理。

**第二輪：時空與後果。**實際核對時間流逝、回程與交通、物資貨幣、裝備、模組、敵我傷勢與死亡、當地社會影響、角色已知與未知、讀者知道但人物不能知道之事。

**第三輪：人物表演與小說品質。**故事有可見神態、動作、距離、選擇、對話，不把設定變成旁白百科；女主也能主動調戲與探索，主角不是每篇都要救陌生人。角色真正做出個人決定，不只是被武器模組和主線推著走。

**第四輪：事件收束與伏筆。**本章確認／排除多少核心問題？有無臨時強加更古老的幕後只為拖戲？伏筆若調整是否同步記錄？此事件何時可以真正結案？

正式長篇按使用者既有偏好使用**可整段複製的 writing block**，場景需要多長便給合理篇幅；若分部須保留時序與角色反應，不為固定字數刪減重要探索與後果。

## 8. 每章交付後：更新正式已發生與尚待回收兩種狀態

必須維護章後追蹤：

| 狀態欄 | 要記什麼 |
|---|---|
| 正式已發生 | 真正寫進已確認正文的事件、承諾、位置變化、人物動作、死亡與傷勢 |
| 人物認知 | 誰知道／不知道／誤認什麼；傳聞不能升成作者世界真相 |
| 裝備資源 | 模組功能與現在實際可用配置、武器形態、錢、能源、行李、醫療與交易 |
| 地理社會 | 哪條路打通／封住、當地人和組織如何反應、貨運與地方秩序後果 |
| 關係 | 兩人是否已交往、共享什麼日常與暱稱、哪些場景真的發生而不只是試寫 |
| 伏筆與事件 | 本篇必答問題、跨事件伏筆預定回收條件、目前高潮與結尾距離 |
| 來源紀錄 | 這章真正讀了哪些檔與段落，哪些重要資料因存取或未定而沒有核對 |

**討論試寫不記入已發生故事進度。**如果使用者確認某篇成為正式章節，正式正文和進度資料可保存 GitHub 相關路徑；正式世界觀設定原檔仍須得到明確修改授權才變動。

## 9. 可執行的最簡工作卡（助手提議，非固定形式）

**寫前**：本章是哪個事件？前章人物與時地？本章相關原檔哪些已實讀？目前有沒有設定衝突？本章要推進／回答什麼？結局與回收方向有沒有保持？

**寫後**：世界／戰力／情感是否符合最新檔？有哪些不可逆傷亡和交通、貨幣、裝備後果？人物知道了什麼？哪些線索留下已規劃的長期伏筆？下一章起點狀態是什麼？

這份工作卡**在作者層使用，不強迫印進小說正文**。實際創作結果與查閱來源須可驗證，不可只說「我記得」或「會遵守」而沒有查核。

## 10. 此次請求與工作邊界

使用者現在要的是**創作方法落地、尊重已有全部設定**，不是立即要求正文第一章或授權把所有待決能力、最終敵人、世界宇宙殼體定案。本輪實際讀了多份核心資料並制定此流程，但**仍須在正式長篇啟動前完成全部 01–31 的逐檔全量盤點**。如果將來存取 GitHub 失敗、舊章缺失或某設定存在衝突，應主動說清楚缺的是什麼，而不是臆測或聲稱全量已讀。

> **最重要的原則：設定必須進入寫作決策；章節必須尊重前後因果；作者層必須掌握事件收束；原檔、後出修正與未決候選永遠分層。**
