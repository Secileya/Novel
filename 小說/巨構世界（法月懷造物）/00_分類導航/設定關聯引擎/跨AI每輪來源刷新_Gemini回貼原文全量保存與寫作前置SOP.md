5. **五階段分開標示**：① 聊天已貼；② GitHub QA／摘要已存；③ GitHub 原文獨立完整已存；④ Drive 相同原文已同步／SHA已驗；⑤ 關聯引擎新增來源與版本鏈／引用已核實。**③ 不等於④，更不等於⑤**。有條件時提交後讀回 GitHub blob，再待鏡像驗收，不得因 Google Docs 額度滿就宣稱全部同步。
6. **存檔完給使用者可查的回執**：至少報新建／已存在、原文路徑、SHA／commit、QA 和索引是否更新、Drive 是否 `CURRENT` 或 `MIRROR_PENDING`、關聯引擎是否已接線。若 GitHub 工具不可用，當輪明言尚未保存，提供可複製來源，不得聲稱背景完成。

**同一篇回貼只是一篇**；「已經貼過」≠「已存完整」≠「已進入最新 Gemini 的 Drive」。回貼原文不能憑助手自稱「我已完整保存」取代驗證。對於只有圖片的 Gemini 長答，可保存截圖來源引用及目前可核的文字，未完整取到的部分應標缺口；不得杜撰未讀句子。

## 五、GPT 修改 GitHub 後，應如何交接給 Gemini？

**這是你要求的重點：不只說「已更新」，而是告訴 Gemini 這題需要讀哪幾份。**

每次實際改動小說設定、候選正文、QA、語氣庫或流程檔，完成提交／讀回後，GPT 應按任務生成一張簡短「來源刷新交接卡」，供使用者複製給 Gemini；可以直接在回答中附上，避免無必要另創 Drive Doc：

```text
【巨構世界｜本次來源刷新交接】
來源：GitHub main，提交 <實際 commit>
本輪更新：<路徑 A>／<路徑 B>（實際 blob SHA）
與你目前任務直接相關，優先全文讀：<相對原始路徑 + 鏡像可檢索名稱>
必要相依／正文：<有效決議／章次全文／道具證據／人物語氣等>
Gemini 端先讀：Drive「00_最新GitHub變更交接.txt」→ 檔案鏡像 → 比對 SHA。
驗證：<MIRRORED_CURRENT / MIRROR_PENDING / READ_NOT_VERIFIED>
後出作者確認：<只列已核准決議，不得填入助手候選>
仍是候選／未完成：<具體項目>
不能自動做的事：<例如不得直接寫正式第13章>
```

- 若 GitHub commit 已寫、Drive 還沒同 SHA：**交接卡仍給出檔名**，但標 `MIRROR_PENDING`。Gemini 必須依實際可讀的最新源判定，不能使用舊鏡像說是最新版；不得要求它直接打開 GitHub，若其工具確實不能。
- 新快速同步 `syncQuick` 及 `00_最新GitHub變更交接.txt` 是**變更提醒，不是向 Gemini 的即時推播或自動記憶注入**。舊五分鐘 `syncDrain`、每小時 `syncHourly` 仍會補檔與巡檢；需查 Apps Script 實際觸發器和 Drive manifest，不因 GitHub Code.gs 有程式就聲稱已部署。
- Gemini 每次開始新話題／收到這類交接卡時，至少驗證當輪任務必要來源的 SHA；同一會話可跳過 SHA 未變且已完整閱讀的檔案。若更改範圍影響人物、章節或容器，必展開上下游依賴，不因只改了一份檔就忽略相關章節。
- **若下一步是寫作**：把上一章候選全文、實際路線、相關人物 059/105、道具證據帳與此輪更新的檔案一起指定 Gemini 讀，而非只給總索引或摘要。這些檔案在 Drive 全部同步後更方便，但「全部已鏡像」仍不等於「這一輪已讀」。

## 六、每輪回覆最少交代哪些事情？（低額度、不中斷創作）

- 簡單問題：直接答，不製造冗長「我讀了哪些」報告。
- **關乎版本與修改／有新回貼**：自然交代 ①使用的現行來源與是否真的讀過；②哪些作者已確認、哪些僅候選；③實際儲存／修改與證據；④ Gemini 需要刷新哪些檔；⑤仍未核實什麼。
- **涉及新創作／連載**：依本 SOP 第三節讀全文與前置，寫後留語氣與連續性回執；不可把抽字串的 CI 說成角色自然度已通過。
- 不用每輪重做35項總整理；可保持研究累積，將有價值的新增成果與原始來源分層保存。

### 實際驗收例

1. **版本改動測試**：GPT 更新作者復歸時間→讀回 GitHub 新 SHA→查 Drive 交接與同 SHA／未同步標籤→ Gemini 用036、088與對應候選章節回答，不拿舊18小時當已確認。
2. **原文保存測試**：使用者貼第三批 Gemini 回覆→找到或建立原文全文→QA另存→報 GitHub SHA、Drive/JSON引是否更新；不能說「有摘要所以已存」。

**底線：有內容才說已讀；有 GitHub 提交與讀回才說已存；有相同 Drive SHA 才說已同步；有關聯引擎新增證據才說已引用；有作者明確批准才說 Canon。**
