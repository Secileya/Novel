## 為什麼單份總結不夠
本庫採用 4 層：**原文真源**（原檔不覆蓋）→ **物理清冊**（不漏檔）→ **原子規則與關聯**（可查觸發、親子／互斥／跨主題依賴、後出取代）→ **每輪審查**（持續讀回原文、擴展所有受影響子單元）。索引不是正文替代品。

## 核心判定的三個獨立維度
| 維度 | 用途 |
|---|---|
| `authority` | 作者明確確認／作者已選未發生／助手候選／原始來源／歷史已覆蓋／未知 |
| `strength` | 硬禁則、人物 DNA、方向已定但原理未決、工作流程、純候選連續性 |
| `story_progress` | 正式已發生／候選稿演示／已選但未正式發生／尚未發生 |

**不能**把 GitHub main 已存、來源說「定稿」、AI 長篇設計、檔案編號較大、圖上有畫、作者表示喜歡某種參考風格，當作同一種「已核定正史」。

## 每輪五關（討論、設計、評審時同樣強制）
**① 識別議題**：本輪涉及誰／物／地點／房間／路線／時間／能力／權限／知情範圍？對應哪一分支及版本？

**② 搜尋與全家展開**：先讀高優先規則、別名與後出勘誤，再搜相關來源；對「房屋」「城市」「世界層」「武器」這種父物件，要求完整子項目清冊：十個房間就十個，不只找文本最像的兩個；同時檢查相鄰關係與上下游依賴。

**③ 權威＋版本鏈**：將兩條衝突說法以 **作者原話／後出修正／既有正式文本**交叉核對，標出 `supersedes`，不能刪舊。諾亞原槍深層同化 B 覆蓋較早安裝即返回傾向是本庫實例。

**④ 主動批判而非順從**：新提案先出「已相容／有潛在衝突／尚缺條件／敘事與世界代價／至少一個更佳替代」，若一切相容也要看與既有物種、經濟、權力、地理、生態會產生什麼連鎖後果；別把建議硬套成下一章情節。

**⑤ 增量寫回**：新設定先標權威與來源，若真更動原 Canon 需作者明確；更新原檔／主題索引／勘誤，對每個受影響實體回查。符合作者 GitHub 工作規則時直接 main，讀回核對，不默默留 PR。

## 真實例子
- **Celeste 不可真正受傷**：她與敵人交手時，只要新稿出現受傷、骨折、被破防等詞，立刻讀 `MG-C001` 來源并標疑似硬衝突；可以是旁人誤判、環境破壞或她主動展示，但不能未經授權真受傷。
- **原槍死亡復歸**：檢索「黑銷／槍身／模組／復歸」須讀 `MG-C007`；深層同化 B 優先於舊傾向，具體同化程度及物件歸屬仍依來源與當下時序確認。
- **屋中十個生態房間（純測試）**：父物件被提及就展開十個 `contains` 子物件，檢查疾病、氣候、供能、管道、隔離、生態遷徙；不得只取房子總描述。測試案**不屬於巨構 Canon**，見 `合成檢索測例.json`。
