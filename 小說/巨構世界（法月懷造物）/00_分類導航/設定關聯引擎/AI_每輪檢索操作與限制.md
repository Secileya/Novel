# 巨構 AI 每輪檢索：實際運作、可驗證邊界與接手方式
> 工具與工作流程文檔，不是小說正史，也不要求本專案的模型寫正文。

## 1. 真正發生了什麼
- `全庫物理清冊.json` 是 Git tree 的 **335 個來源檔案快照**（建立時已列路徑及 SHA，並不代表全部已完成設定權威判讀）。
- `高優先規則與關聯.json` 收錄首輪 21 條來源可追的高優先約束；**僅是種子**，未收錄者仍必須從原始檔查。
- `創意相容性台帳.json` 放入 W01 十二區、舊九區及早期生態候選。**新版主體優先不等於舊生態全廢。**
- `查詢.mjs` 是**真正掃描本機 Git checkout 檔案全文的查詢器**。它不靠 AI 自己記住所有檔名，可以從別名、主題詞、角色實體、關聯邊、候選創意及全文詞彙找路。
- 程式能掃描文件、列依據、展開容器子節點；**不能自動做完整語義判斷**，也不能證明沒安裝此工具的 AI 一定會調用它。

## 2. 如何跑（任何能 checkout 此 repo 的終端；Node.js 20+，不用安裝套件）
從 `小說/巨構世界（法月懷造物）` 執行：
```bash
node "00_分類導航/設定關聯引擎/查詢.mjs" --check
node "00_分類導航/設定關聯引擎/查詢.mjs" --self-test
node "00_分類導航/設定關聯引擎/查詢.mjs" --query "Celeste 和強者對打，她會不會受傷？" --receipt "本輪檢索回執.json"
node "00_分類導航/設定關聯引擎/查詢.mjs" --query "把舊的機械森林與微小生態放進 W01 十二區是否合理？"
```
`--check` 檢查索引中的必要來源是否能在本地找到、W01 是否正確有12+9兩套子項；`--self-test` 包含不可受傷、原槍深層同化、地圖及房屋十室的**隔離測試**。查詢輸出 JSON，`--receipt` 可另存查詢證據到指定位置，預設只輸出終端不改原檔。

## 3. 它怎麼知道該查什麼？
- **誰**：辨認 Celeste、諾亞、艾莉維亞、原槍等別名，沿 `高優先規則與關聯.json` 一階關聯檢查。
- **在哪**：辨認 W01 或某區時，`container_expansion` **展開完整十二區**，附舊九區及候選狀態；不因搜尋評分只抓前兩個區就把十區忘掉。
- **什麼約束**：比對 `claims` 的 subject / trigger；會附原始來源路徑，硬規則衝突僅標需審查，不能無來源宣稱已判決。
- **舊創意**：按候選池的 tags / possible_placement 收錄，如根橋、巨龜、微生物、機械森林、醫療蟲等。提案需要判斷是否可以安置，不替作者採納。
- **漏掉關鍵詞時**：查詢器仍以中文二／三字片語掃描整個物理檔案目錄，回傳有分數的來源；**但語義等價、諧音或完全未知別名仍可能漏檢**。若查不到，不等於作品不存在此物。須補充別名與人工主題掃描。

## 4. 我怎麼知道 AI 真的查了？
必須同時看到以下**同一次討論**的資料，而不是只聽它說「我讀過」：
1. 它實際執行查詢、或在只支援 GitHub connector 時逐檔取回**相同用途**的原始來源；
2. 回覆附上 `query`、`git_head`、`files_actually_read`、`relevant_claims`、`container_expansion`、`selected_sources` 的實際查詢回執／可驗證來源；
3. 指出舊版如何處置、新提案對既有生態／社會／人物會產生的後果，以及哪些尚未閱讀或仍待作者決定；
4. 若新增設定，GitHub 原始設定與主索引更新、衝突對照、讀回驗證才叫完成寫入。

**注意**：本機程式輸出可由真正執行者提供；單獨的 JSON 回執也可能被人偽造，沒有執行記錄／GitHub來源比對就不能作絕對證明。該程式跑完不代表 AI 真的理解全部文字。

## 5. 不同 AI 客戶端的真實限制
- **Coding agents / IDE**：在本 repo 工作、願意遵循 `AGENTS.md` 的代理，可以執行上述 Node 指令並每輪回查；`AGENTS.md` 並非所有 AI 都會自動讀取。
- **ChatGPT 新對話**：即使 GitHub 已連接，也**不能保證新對話自動讀這份檔案或執行本機 Node**。讓它先取得專案 `AGENTS.md`、本檔與 JSON，再按本輪問題用 GitHub connector 讀相應原文；若有 Work/本機 repo 能直接執行則更好。
- **Gemini 或其他模型**：需要其接入同 repo 的工具或上下文。只有一段聊天提示詞、只存在 GitHub 的檔案，不會神奇改變模型的內部持續記憶。
- **GitHub Actions**：CI 可以測試查詢器是否仍能在 repo 上跑通，但無法證明任何聊天模型在某次推理真的調用它。

## 6. 強制回覆中的小型檢索摘要
任務不是正文創作，也應先在內部做 `人物／場景／地理／生態／物件／權威／時序` 的影響面擴展，完成後向作者用兩三句或一小段報告：
「本次讀取哪些來源、哪個 Canon 有效、哪些早期素材仍可回收、有哪些真衝突或待核、是否已保存」。若來源不足，要說「本輪尚未驗證X」，不能用沒有衝突四字掩蓋沒讀到。

## 來源更新與索引過期保護
查詢器除了每次掃描實際檔案，還會用 Git 提交中的來源 Blob SHA 對比建立清冊時的 SHA。若任何原來源被修改、增加、刪除而結構化規則未同步，`source_index_drift` 會列出變更清單，`--check` 失敗，查詢狀態不再宣稱完整。**不代表設定真的互斥**，而是要求重新核對受影響規則／創意與版本後更新清冊。本機未取得 Git checkout 也不能假稱已驗證版本。新增的候選生態與社會素材總數目前 30 組，詳見 `創意相容性台帳.json`；這仍不是「全作品所有原子設定已整理完」。
