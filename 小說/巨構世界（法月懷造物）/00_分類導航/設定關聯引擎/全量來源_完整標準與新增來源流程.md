> **最高優先級工作規範，非小說 Canon。** 使用者在2026-11-09明確糾正：最終目標**不是僅清完原171份**，而是**所有原始來源，包括過去164份「已引用」來源、原171份用途卡來源、未來每次新增的文件與圖片，全部達到同一套完整的來源語義審核、版本仲裁、跨文件關聯與實體圖／依賴圖回接標準**。來源數量會動態變動，335只是當時快照，並非上限。永遠不能把「已有原子引用」當作「全文已完成」。

## 一、唯一不混淆的真實進度

歷史335份 = 過去有至少部分細粒度直接引用的164份 + 過去需建立用途卡的171份（兩組恰為原始檔案劃分，不代表審核質量排序）。
171中目前2份有附原始SHA、逐行覆蓋、後修SHA及圖譜關聯的編輯性整檔驗收紀錄；其餘169份尚未通過。歷史164份**目前無相同整檔驗收證據**，必須列入待審。
因此當時真正可以證明的全體完成度是**2／335，尚餘333／335份**。不是164份已完成，也不是只剩169份；尚未驗收不等於完全沒讀過。

第四至七批的**68**是「定向語義審核命題數」；**188**是支持那些命題的原文SHA＋行號錨點數；**164條新建立的圖譜連線**是這68項審核通往已存在領域節點的範圍性回查連結。三種都**不是完成的檔案數**。不做循環換算。

每輪從有Git checkout的專案根執行：
```bash
node "00_分類導航/設定關聯引擎/全量來源_動態納管與驗收.mjs" --summary
node "00_分類導航/設定關聯引擎/全量來源_動態納管與驗收.mjs" --next
node "00_分類導航/設定關聯引擎/全量來源_動態納管與驗收.mjs" --report > /tmp/giant-world-all-sources.json
node "00_分類導航/設定關聯引擎/全量來源_動態納管與驗收.mjs" --check --negative-test
node "00_分類導航/設定關聯引擎/AI接手_整檔語義驗收.mjs" --negative-test
```
* `--summary`為預設，`--next`列優先批次，`--report`列目前**每一份**來源的來源SHA／歷史群組／已審議題／圖譜映射／需補工作。舊版`171`數字只能作歷史子集切片。
* 沒有Git checkout時應直接讀GitHub當輪main、工作板與CI，不能宣稱已執行本機命令；若不能計算最新全集就說明工具限制。
* 程式從**當前Git提交樹**發現專案根下全部來源檔案，僅排除設定關聯引擎本身和用於AI執行指示的`AGENTS.md`／`GEMINI.md`。原始335份的類型：318 MD、6 JSON、8 SVG、3 TXT。新加入的md/txt/json/svg或其他檔案、圖片與未知格式**都會納入動態待審**；後者需專用影像／二進位驗收，絕不能拿文字逐行驗收假冒已看圖。源檔沒有加入Git前不會被此Git提交樹掃描發現。
* 新增檔案自動以`NEW_SOURCE_AUTO_QUEUED`計入待審數；原始SHA或後出權威來源變動可令舊驗收撤銷／列回待審。此機制在每次工具／CI實際執行時生效，**不是背景常駐監控、也不會自行撰寫完整設定**。

## 二、全體同一驗收標準（工作量可依檔長伸縮，質量不可降級）

任何原始檔只有達到以下全部條件，才能在全域計入一份`FULL_FILE_EDITORIAL_ATTESTED`；只交來源標籤、搜尋索引、幾條命題或一條圖邊都**不得**通過。

1. **完整來源**：保存精確路徑、Git blob SHA、原始文字／原圖保全方式與來源種類。全文各段逐一核對；若原始長檔內含多位AI互動、外部轉貼、不同日期、更早版本，須分開標記，不讓它們互相覆蓋。Markdown/純文字/JSON/SVG具可檢查的全行連續覆蓋；圖片或非文字則須原圖、影像內容、可重現視覺驗證與文件化觀察，不准造假完成。
2. **權威與時序**：對每個實質主張分開判定`authority`（作者直接決議／待決／AI提案／二手研究等）、`strength`及`story_progress`（正式發生／已選但未發生／候選／純研究）；依後出修改核對適用範圍，列出被取代與仍可保留的舊創意。
3. **原子命題與跨文衝突**：將有價值的具體內容逐條抽出，重要人物動機、說話方式、世界本體、科技武器、限制、事件先後、道具物權、組織與物流、社會生態以及沒有答案的伏筆都要回查；提供可驗證SHA／行號或可核的影像位置。不因文字長就只擷取第一頁。
4. **完整圖譜回接**：把該份每條重要命題依其實際證據連到既有`高優先規則與關聯`、`人物組織與社會關係圖`、`人物時期與知情矩陣`、`版本取代與相容決策鏈`、`容器與子單元登記`、`生態產業與制度因果網`、`跨層文明生態依賴網`或候選逐場道具帳等相應節點。無相關實體時可建立明確、具名、可查的非Canon知識節點或表明尚待建節點，**但不能假裝已有全圖回接**。不能以人物同名、設定相似或上下兩層就創造未證明的因果、交通、時空同步或Canon。
5. **雙向依賴與變更影響**：必須能從「來源→原子命題→實體／版本／時期／依賴」及反向「實體／命題→來源及原始證據」找到對應。變動時標記受影響的索引、候選章、下游依賴與既有完成證書，確認是否需要撤銷重驗。全文已完不代表關係將來永遠不變。
6. **單檔可驗收紀錄**：在`AI接手_整檔語義驗收台帳.json`為**該份本身**登記完整覆蓋區段、代表引文、後出來源SHA清單、相關審核命題、圖譜端點、未解問題及AI編輯性簽核；由`AI接手_整檔語義驗收.mjs`與全量動態掃描器、查詢器測試及CI核對。原稿原始位元不經允許不改寫。通過後才從全域待審總數扣一份。

原稿類型不同可以有不同的**查證工作量／專用手段**：25行舊校訂檔不用像20萬字對話合冊一樣耗時；但每份都必須涵蓋全部本檔有意義的內容與跨來源依賴。某文件只能證明「這是助手候選」也可以完整驗收；**完整驗收指整份來源被準確處理，不代表內容被作者批准為Canon**。

## 三、實際執行順序（不照164→171刻板流水，也不只挑最短兩份）

1. **S0 動態掃描全集**：以最新Git HEAD枚舉全部來源，基準335可增。標記歷史164／171／新增三個不同的**來源出身**，但三組皆進同一待驗收池；舊的細粒度引用僅是可節省回讀的先前成果。以全域已通過／總量為主指標。
2. **S1 用依賴與風險排批**：先新檔、被修改而失效、作者明確後修、對多人物／地理／候選版本造成廣泛影響的來源，再優先處理重要而未驗的舊檔；將同題的歷史164與171**混合成批**、直接回用前幾批已建立的錨點與關係，不重造。一次可以讀多份，實際每份完成數由證據而非批量大小決定。
3. **S2 實際逐檔讀完整內容**：逐段建立原文與版本位置，讀相關後修及競爭候選；需要時讀完整原話，尤其用戶的直接決議高於AI自說自話。長檔可跨數輪，但明確留下尚未覆蓋的段落與條目，不假稱整檔完成。
4. **S3 原子化＋衝突仲裁**：把每個重要主張登記SHA/行號、權威／時間／成熟度／正文進度、哪些舊版過期哪些仍可回收，涉及未決事項保留待作者而非AI創造答案。
5. **S4 全圖回接與反查**：既有實體和父容器可擴展所有子項；新的真因果、社會權限、跨世界層、物件狀態必有獨立充分證據；候選只建候選相關性，不升格正式Canon。新增審核批次須補`審核命題至既有關係圖_雙向證據橋.json`及查詢器驗證。
6. **S5 單檔驗收**：每份逐段／逐影像核對完、無遺漏、後修及圖連線核實才計為`FULL_FILE_EDITORIAL_ATTESTED`；若仍有不可裁決但已清楚存證的候選差異，可保留`OPEN`而仍對已知內容完整分類，是否足以簽核由編輯標準決定，不必把所有未決當作者已採案。
7. **S6 GitHub 回寫、CI、交接**：原子提交非Canon索引、台帳、圖邊、驗證測例；核對最新HEAD及Actions。每輪固定回報「實際讀取N份／完成整檔M份／主要新增命題K項／已連圖P條／總數動態變動／剩餘X份／下一批具體檔案」。無工具不能宣稱完成。

## 四、增量新設定與失效撤銷

* 任何新檔先在**當前Git提交樹**出現，動態掃描器立刻在下次`--report/--next`及CI執行時把它列入待審；無需手改335數字，也不因檔名沒在舊171清冊而漏算。
* 新文件與舊設定矛盾：先確認是否有**作者明確後修的權威覆蓋**，以適用範圍形成版本鏈，回查被影響的來源／事件／人物／地理子單元；不同答案可屬不同候選版本，不強制合併。
* 舊已驗收文件若源SHA、任何列為權威依賴的後出文件SHA或圖譜關聯失效，改為`REVOKED_RECHECK_REQUIRED`，重新列入待審。**Git提交成功、CI通過不能代替人類／AI對意義的實際重讀**。
* 新的圖像、音影片或二進位附件在此全部算作來源待審，但**文字行號驗證器不支援它們的完整內容**；接手AI需用實際可檢視媒體工具、做來源／版權與視覺內容核對、另建同等門檻的媒體驗收器。缺工具時保持待審，不自動簽核。
