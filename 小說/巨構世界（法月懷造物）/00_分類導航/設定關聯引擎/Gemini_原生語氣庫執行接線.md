# Gemini 直接執行巨構語庫｜網頁版 Gem／專用 Skills／Gemini CLI

## 決定與邊界
這不是「要求 Gemini 每章說出我去」；是讓 Gemini 在**寫作前真正見到105/059的原文**、寫後回頭核對人物表演，並留下查閱憑據。2026-11-09 第01–12章由 Gemini 生成，但過去生成時是否讀過語庫沒有可核實的書面紀錄，**不能靠今天的詞頻反推**。

## A. 不裝軟體：Gemini 網頁版 / Gem（最適合目前工作模式）
1. 在 Gemini 網頁版建立一個自訂 Gem，例如「巨構世界｜小說與語庫」，將[可複製指示](Gemini_Gem語氣庫_可複製指示.md)的正文放進指示欄。
2. 在 Gem 的 Knowledge 加入 **105 全文、059 全文**；可再加 058／093／104 和正式現行規則。最好用可以更新的同一組來源，不依賴只有檔名的連結。若附 Google Drive 文件，官方說 Gem 可使用後續更新的 Drive 檔案，但前提是事先真正設置 Drive 檔案與權限；本 GitHub 原稿不會自動同步到 Drive。
3. 新任務要求「先依105/059看語氣，再寫／再審」，並要求最末列出**實際讀到的來源、至少兩句本稿真台詞和判斷**。無法讀檔應標 NOT_VERIFIED。
4. 也可在一般 Gemini 網頁版「匯入 GitHub repo」後額外貼本文[示範檢查提示](#可以直接貼給普通-gemini-聊天室)，但**GitHub 匯入是當次快照，不能自動同步更動、不能直接回寫 repo**；Gem 的 Knowledge 是否自動持續取GitHub新檔不能假設。
5. Gemini Apps 若帳號有「Skills」功能，可將同一段流程存成 Skill；功能可按任務套用，但仍要供給實際來源檔，不等於 Skills 自動讀到最新 GitHub。

## B. 有本機 Node／Git：Gemini CLI 自動讀取項目規範＋一條命令
從 `Secileya/Novel` 的 **Git repo根目錄**（`.git`所在目錄）啟動 `gemini`。CLI 官方支援遞迴情境檔 `GEMINI.md`，本專案自己的 `小說/巨構世界（法月懷造物）/GEMINI.md` 已有寫前檢索規範；請先讓 CLI 打開該檔，可以用 `/memory show` 確認真正載入，沒有就明確要求讀。命令放在Git repo根目錄 `.gemini/commands/mega/voice.toml`，啟動後輸入：

```text
/commands reload
/mega:voice 09
```

`/mega:voice` 使用 Gemini CLI 原生 `@{檔案路徑}` 將第105、059全文與審核流程**注入提示**，再讀指定候選章節；它不強制插詞、不自動修改原文。若希望先從本地安裝官方 CLI，可按官方文件 `npm install -g @google/gemini-cli`；此 GitHub 提交不代表本機已安裝、Gemini 已認證或已運行過。需要適當授權和網路環境。

## 可以直接貼給普通 Gemini 聊天室
「請先實際閱讀我提供的第105語庫全文與第059份後出語氣規則，再閱讀本次要處理的小說場景。請依人物當下的關係、情緒、身體狀態與目的決定用語；『我去／媽耶／哎不是／你丫』及各種標點只可自然選用，**不用也完全沒問題**。檢查至少兩句真台詞是否貼合她的性格，有問題才提出可選修改。請在回答末尾明確寫出你**實際讀到**的來源檔名與本稿原句；讀不到任何必要來源就寫『未驗證』，不可假裝已查閱。保留全部候選／非Canon及PREWRITE HOLD。」

## 避免誤解 CI
現有[回溯用詞檢查](檢查候選正文語氣庫參考.mjs)只核第01–12章原始版本SHA與用詞分布，**無法證明 Gemini 過去如何思考**。本次另外加的 Gemini 接線驗證只檢查執行指示檔、來源引用路徑和可用命令格式；**CI通過不等於Gemini本人已登入或執行**。真正 Gemini 操作需要打開Gem／CLI、餵給來源並得到其輸出，才能把那一次記為「已執行」。

## 資安與權限
專案根本不需要 API key 才能把指示與自動載入命令存進 GitHub；如要排程呼叫 Gemini 模型，則另需用戶具名授權、可用的模型存取及 Secret 配置，不要把認證資訊明文存入 repo。長篇候選仍不能自動升為正史。
