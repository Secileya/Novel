# 批量整檔審核 v2｜效率提升與防漏驗收

> 2026-11-09 起適用 NEXT-009。工作規範，非小說 Canon；不能將 CI 成功等同 AI 已理解全部語義。

> **2026-11-10 實際操作順序與缺口**：見 [第25、26批真實實作對照＋S0～S4](20261110_第25_26批真實執行對照與現行SOP_非正史.md)。第25、26批雖經CI成功，仍存在四類第二遍問題及版本impact措辭過度通用的待補強之處；不得把套話記錄當作充分語義驗證，也不得重新把同原文算成新驗收。

## 為什麼改
原有驗收能證實 SHA、全行區段連續、單條代表引文及後出來源指紋，卻不能從這些形式證明區段內每個重要命題都已回收。跨批次同題來源亦可能在較晚審核時暴露前批未曾發現的依賴。

## 新規則
1. **排批可大，驗收逐檔**：以實際行數、跨源依賴、風險和媒體類型排批；以約 2,600 行／至多 12 份作首次測試工作量參考，絕非上限，也不是每輪必須驗收12份。可同時啟動多份；不能因為一批共讀而一鍵讓所有檔案通過。
2. **兩遍語義檢查，明示同一 AI 的限制**：第一遍讀所有段落、辨權威及有價值主張；第二遍從「哪些重要東西沒抽出」反查。必留四類具原文行號的反問：作者與助手界線、後修版本、重要命題漏檢、跨文件影響。這是第二輪核對，不冒稱不同人工審核者獨立複驗。
3. **逐區段實質檢查點**：每個全行覆蓋區段至少一項帶原文引句、行號、權威分類與實際語義結論的主題證據，超過70行至少兩項；無圖節點的內容須具名解釋，而非捏造相似關係。程式只能檢查可追索性，仍須 AI 真正讀完原文。
4. **跨批次版本依賴反查**：已列為後修權威的每個依賴來源，須寫明版本指紋與影響；若依賴後來修改，原有退回驗收仍適用。新增 `--impact` 可以列出已登記的直接／傳遞受影響驗收檔，但沒有入圖的隱藏依賴必須另作語義回讀。
5. **新舊驗收分層**：截至第八批原六份維持 v1 證據與既有有效狀態，未自動補簽 v2。從本流程開始新增的 `FULL_FILE_EDITORIAL_ATTESTED` 必附 `semantic_quality_v2`；失敗者留在待審，不能以任務達標率硬簽。
6. **可回復、可驗證（現行SHA分片）**：不修改作者原稿／候選章，原本巨大舊總帳及舊證據橋唯讀；先以排批防重預檢排除已接受來源，再建立原文→命題→既有圖關聯→依賴的單批JSON分片；在掛入Manifest前先用 --candidate 核來源SHA及重覆。一次更新 Manifest、工作板、覆蓋率、日誌及自動交接，再原子 commit 到 main；以CI成功和讀回確認後才報驗收。正式0章／PREWRITE HOLD。

## 操作指令

批次選取前先執行 `AI接手_排批防重預檢.mjs --check` 與 `--select`；產生新分片但**尚未加入Manifest前**再執行 `--candidate`。CI有永久負向測試，但不能把提交後才發現重覆當正常流程。使用GitHub連接器時應做歷史總帳＋全部Manifest分片的等效SHA來源聯集檢查，不能聲稱跑了本機Node。

從巨構專案根（完整 Git checkout、Node.js 20+）：
```bash
node "00_分類導航/設定關聯引擎/批量審核_語義缺口與跨批影響.mjs" --plan
node "00_分類導航/設定關聯引擎/批量審核_語義缺口與跨批影響.mjs" --check --negative-test
node "00_分類導航/設定關聯引擎/批量審核_語義缺口與跨批影響.mjs" --impact "03_人物關係與語感/105_對話語庫_莉雅口語素材_標點節奏咬字與情境演出.md"
node "00_分類導航/設定關聯引擎/全量來源_動態納管與驗收.mjs" --report
```

## 完成口徑
報告「本輪排入 N 份／實際讀完 X 份／v2 新通過 Y 份／未完成 Z 份／本輪命題與圖邊／來源指紋與提交／最新 CI」。新 v2 證據的個別 `material_units`、`countercheck_questions` 及 `dependency_impact_review` 一律可追原文；不能只複製模板或把零風險宣告當檢查完成。跨組並行時先在同一批整合衝突及共用後修，再逐檔簽核，避免對相同原文重做抽取。
