# 舊資料專用勘誤 03｜至第 100 份仍可維護的無損增量版本程序

> 建立：2026-10-19，依使用者明確要求「不精簡內容、不刪改成立的內容、舊資料單開、錯誤過時矛盾必須可查、根索引要維護」。以實際整個巨構世界 01–58 逐檔首輪回查及 [59 最新要求](../59_最新確認_雙主角語氣頻率_靜謐迴廊巨幅雙提升_全庫稽核要求.md) 為基礎。**這是一套對 GitHub 作者資料的維護流程，不是小說世界內規則**，也不更改總小說工作流程 [NOVEL_WORKFLOW_PROTOCOL](../../00_總索引與交接/NOVEL_WORKFLOW_PROTOCOL.md) 的正式寫作要求。

## 1｜檔案職責，不要在 00 索引寫 100 篇超長「最新版」矛盾段落

- **01–11＋家庭正式檔**：正式基底與正式修正；已成立原文原則保持完整，未受明確授權不可自行改寫。
- **12+ 編號檔**：保存使用者討論、原話、全長候選設計、研究及測試場景；即使後來有新版本，仍可查當時論證，不為省篇幅清空。
- **[00_現行決策與主題索引](../00_現行決策與主題索引.md)**：**第一入口**，按主題指出目前使用者明確有效的規則、來源原檔、明確未定項、容易讀錯的舊項；不能把來源細節濃縮成無法還原的短答案。
- **[00_全檔清冊](00_全檔清冊與版本狀態.md)**：**每個原檔一條連結及主要權威風險**，讓歷史都可保留。
- **[01_後出勘誤](01_後出取代與明確錯誤.md)**：只有**原有肯定被用戶更正／助手發現文本自己有矛盾**的特定條目，用穩定 ID 記錄舊說、後出證據與保留部分。
- **[02_候選隔離](02_候選與未決隔離.md)**：助手完整設計及仍未選項，不因最近討論最多便自動定案。
- **原 [00_導覽與狀態](../00_導覽與狀態.md)**：**全份數字編號索引**與背景參照，要保留每份的長描述，可加醒目指向新入口，過去時點的摘要可標舊版本，不反客為主。
- **[00_專案交接](../00_專案交接.md)**：新模型首先知道「目前在哪、最短閱讀路線、未同步 dirty flag 與下一個實際動作」。不應每回都機械把所有舊段落再貼一次；**若同一檔上下兩種互斥說法，必須立刻明示較舊段落失效**。
- **第 [33 舊全檔稽核](../33_正式寫作準備_現行設定全檔稽核_版本與未決清單.md)**：永遠保留其截至當時的完整工作紀錄；不再當現時設定裁判。

## 2｜以後每當新增第 60、61、100 篇時的固定流程

1. **先分類新消息**：已明確修改、已明確新增、純候選、純疑問、已完成正式正文或研究需求；保留使用者原話及範圍。**後來助手想得很完整不等於使用者已同意**。
2. **先 TOPIC_SWEEP，而不是漫無目的讀完所有檔**：查 00 現行入口，搜同主題關鍵字和已知別名（如「Path of Pain／苦痛之路／靜謐迴廊」；「終焉迴廊」作不相同對照），讀同主題的最初明確設定、中間變體、最新後修及確定衝突條目。若涉及多支鏈（如兩位主角復歸＋兩座迴廊＋武器）都要做交集核對。
3. **寫內容完整的本輪新編號討論檔**：不因過去有 60 份而縮短應有的人物、技術或對話，使用者要求「保留幾十份」即可。標明本輪確定／助手候選／真正未決以及引用來源。
4. **先找是否要新增勘誤**：如果新消息更正先前某筆，向 01 勘誤追加具有穩定 ID 的條目，精確連向**舊原檔及新來源**；如果只是提供一種新候選，更新 02 隔離而非寫成「舊設定作廢」。
5. **不破壞歷史內容**：舊檔可以只在**最上方加一條短醒目後出提示或在尾端加備註**，不刪除正文、有效場景、原始發言、舊方案與圖片說明。舊檔若是同一段「現行」明文錯誤，應清楚標示**這一句現已失效**，而不能當兩個可自由選的現行規則。若用戶另有明確「改寫原正式設定」授權，才按其範圍修改正式檔，並保留歷史版本可追溯。
6. **更新雙索引**：根 00 導覽加新數字檔案的長說明，00 現行入口修主題最新採用／禁用與來源，舊資料全檔清冊新加一行／勘誤條目按需補上，00 交接更新最短閱讀路徑與 dirty flag，必要時更新 master 指向但不要讓其他分支混入。
7. **GitHub 實際讀回確認**：每份涉及檔案寫入後讀回檢查，確認連結存在、最新修正被標識、資料完整、該有的索引／交接已同步。無法完成寫入時必須誠實標記**DIRTY**，而非說全部完成。
8. **寫正式正文時額外遵循總流程**：本程序縮短一般設定討論的查找路徑，**不取消正式小說的 PREWRITE_GATE、來源／角色矩陣、正式章節全文和連續性核對**。如果完整差分很重要，仍需詳讀相關所有原文，而不是只讀 00 摘要。

## 3｜定期全面稽核與觸發條件

- **每一項後出修正**：做它的專題全庫查找，包括舊拼法／暫名／英文別名／已被廢掉的公式；直接指出有那些舊檔需加警語。
- **每新增約十份討論（例如 70／80／90／100），或跨數領域更動**：啟動階段性全檔稽核，包括從上次整體稽核後所有新檔、根 00、舊資料勘誤總表，以及與新修正相關的更早原檔。重要領域跨越時可提前全面掃描。
- **正式第一章開寫／大幅改寫**：依總流程做 PREWRITE 及相關原檔全面比對，不用約十份的節點代替正式 gate。
- **發現疑似矛盾**：先對比兩者時間、是否為用戶明確或助手候選、所指的概念是否真相同。若能共存（如一處可同時有白橋、另一處另有單向機關），則在 02 標「**不同場域**」即可；若真正互斥，列 01 條目並明定現行依據。
- **對外宣稱稽核範圍應精確**：可說「2026-10-19 已逐檔核查 01–58 的主要權威／版本衝突」，**不可說任何一句設定都已全文無差錯或所有歷史原始聊天已完整復原**。

## 4｜不可自動採用的「修正」：避免稽核反而破壞既有世界

- **整理不是精簡**：禁止把已有幾千字的完整候選／場景拿掉，換一個 50 字摘要。現行入口是**導航**不是一套新代替原文的百科。
- **同一人不同狀態不自動矛盾**：人物可以在不同階段／場合爆粗口或深情，不能為了統一口癖刪掉老互動。
- **世界格局大小不等於每處都要超十級**：必須區分文明層次、武器個體性能與戰鬥局勢。
- **同詞不同空間不自動合併**：靜謐迴廊與終焉迴廊是兩處；當發現舊代稱「苦痛之路」時須指向靜謐迴廊。
- **無已發生正式小說章節**：任何試寫不因保存於 GitHub 而上升為正式已發生事件。
- **正史與跨分支角色繼承**：只依本分支及上位家庭固定設定，不能把其他兄弟世界線的演出無條件寫進巨構。

## 5｜未來每輪最短可核驗輸出格式

**已新增檔案：**數字編號、長描述、具體 commit；**更新過時舊檔：**列路徑及是頂部標註還是追加勘誤；**未動的正式 Canon：**保留有效內容及原因；**未決：**尚待使用者指定哪個技術、角色或場景；**同步狀態：**根索引／現行入口／勘誤／交接全部成功讀回方可稱 CLEAN。若有任何單步失敗，列失敗項並明確標示 DIRTY。
