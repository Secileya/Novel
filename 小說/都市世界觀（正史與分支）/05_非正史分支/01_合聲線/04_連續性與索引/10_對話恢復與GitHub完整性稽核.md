# 合聲線・對話恢復與 GitHub 完整性稽核

> 用途：補足「GitHub 可能漏存舊都市合聲線討論」這一層。  
> 本檔不是正文，也不是把所有聊天內容自動升格為正典。

## 觸發條件

只要使用者出現以下任一意思，本檔自動觸發：

- 「之前我們討論過」
- 「去讀都市合聲線那個對話」
- 「我記得有叫你存 GitHub」
- 「這個流程漏了以前討論」
- 「看看舊對話還有沒有漏存」
- 「沿用之前那個對話的設定／說話方式」

觸發後，**CONVERSATION_RECOVERY_GATE 必須先於 PREWRITE_GATE**。

## 恢復程序

1. 先定位使用者指向的舊對話／相關歷史內容。
2. 能讀多少讀多少，但不能只取前段；尤其要追後續修正與否定。
3. 每項內容標記：
   - 定案
   - 後修
   - 候選
   - 作廢／拒絕
   - 未定討論
4. 與下列 GitHub 檔案比對：
   - `00_合聲線設定.md`
   - `00_專案交接.md`
   - `01_當前狀態快照.md`
   - `02_未完成因果與伏筆.md`
   - `03_角色知識矩陣.md`
   - `04_修正與禁用設定.md`
   - `05_交易與資產台帳.md`
   - `06_章節續寫索引.md`
   - `07_2026-09-20_對話設定完整補錄.md`
   - `08_後續候選與參考規劃.md`
   - 正式正文
5. 漏存定案 → 補檔。
6. 舊版已被後修 → 更新／禁用，不保留成現行設定。
7. 候選仍是候選，不得因「曾討論」變成必發劇情。
8. 與正式正文衝突 → 先記錄衝突，**不得私自改正文**。

## 2026-09-21 已確認的近期補漏

### A. 羅蘭／安吉莉卡與「被觀察」的知情邊界

- 目前規劃**不是**「羅蘭與安吉莉卡一開始就知道有人正在即時監視自己」。
- 正確初始推論是：里恩在 Canto IX 重演一套本世界不存在、卻與另一世界羅蘭／安吉莉卡人生、家庭與戰鬥高度重合的模板。
- LCB 日後以里恩的客觀資料查圖書館，相似性索引才可能返回「來源：非本世界」的館藏。
- 羅蘭／安吉莉卡之後得到的第一層情報應是：**某個未知來源／機制取得並使用了另一世界的他們作為人生模板。**
- 這不等於「對方正在看現在的他們」。
- 只有未來出現額外證據，例如指令即時反映本世界羅蘭／安吉莉卡剛做過、且外界正常資訊渠道不可能知道的私人行動，角色才有充分理由升級懷疑為持續／即時觀測。
- 跨世界館藏本身不能當作即時監視證據，也不能當本世界孩子真兇證據。

### B. 「腦葉公司那種事」的現行解讀邊界

- 阿莉莎／研究設施相關語境中的「不想再看一次腦葉公司那種事」，目前只固定為：**舊 L 公司／腦葉公司曾有嚴重設施與收容災害，霍恩海姆因此把現在 LCE 的警報／備援安全設得非常敏感。**
- 尚未鎖定成某一場具名的腦葉公司事故。
- 尚未建立「霍恩海姆本人親身經歷那場特定事故」。
- 後續若要補成具名歷史或個人經歷，必須有新正文／設定因果，不得從這句話自行反推。

### C. 流程本身的補漏

- 先前只建立 PREWRITE／POSTWRITE，仍可能完整讀完一套「本身已漏資料的 GitHub」。
- 現在改為：**必要時先 CONVERSATION_RECOVERY_GATE → 再 PREWRITE_GATE → 正文 → POSTWRITE_GATE。**
- 使用者不需要每次重新提醒；只要語義觸發即執行。

## 恢復後必做：主題式 GitHub 回查

舊對話恢復後，不能只把「我剛讀到什麼」和交接摘要相比。

對每一個恢復出的重要主題，還必須：

1. 用正式名／舊名／外文名／能力名在 GitHub 做定向搜尋；
2. 找出穩定設定、詳細補錄、修正禁用、後續候選與正式正文中的全部高相關命中；
3. 判斷 GitHub 是：
   - 已完整保存；
   - 有保存但被壓縮到容易誤讀；
   - 漏存；
   - 留有被後修淘汰的舊版；
4. 若 GitHub 其實早已有內容，明確承認是「先前檢索漏讀」，不能說成「現在才新增設定」；
5. 把這些主題送入 `TOPIC_SWEEP_GATE`，完成狀態／衝突核對後再續寫。

**恢復舊對話的目的不是重新發明設定，而是驗證 GitHub 是否完整，以及模型是否真的把已存在資料抓進工作上下文。**
